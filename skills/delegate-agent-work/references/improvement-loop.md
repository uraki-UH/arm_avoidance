# 品質を維持する指示改善ループ

対象はユーザーが依頼した指示書・評価タスクの改善。単なる開発タスクに、指示最適化の比較実験を自動追加しない。

## 既定のローカル運用

通常作業で既に生成された記録を、追加モデル呼出しなしでローカル集計。使用量、所要時間、成功・失敗、固定品質指標だけを許可済みの集計として扱い、生ログ・コード・入力・正解・スキル本文は別AIへ転送しない。会話へのツール出力も送信に相当するため、生データを読み出す集計はPC内で完結させ、表示は共有可能な集計値だけ。

取得できないCodex使用量は不明。使用量を測るためだけの新しいCodex CLI・API・サブエージェント呼出しは禁止。共有可能な集計からこの会話で改善候補を検討し、許可済みの通常作業で次回の品質・使用量を観測。条件が異なる作業の比較は参考値とし、同条件の節約効果を実証したと断定しない。

既存のAI比較runnerは外部送信を伴うため、既定では実行しない。以下の候補生成・固定入力の比較手順は、共有可能なペイロード・宛先・用途について個別に許可された場合の手順。共有不可の内容をそのモードへ持ち込まない。

## 分担

主担当が固定仕様、品質基準、評価セット、比較条件、上限を管理。改善役は候補指示だけを作成。実行役は固定入力・候補指示を使う試行。モニターは評価器とusage集計を基本とし、不一致や採否の解釈だけを独立評価役へ委任。

既存の`tools/skill_optimizer`には、改善AI・作業AI・決定的評価器・上限管理の実装がある。既存実装があるリポジトリでは、その`skills/optimize-agent-instructions/SKILL.md`と実行ガイドを先に確認。役割の概念が同じでも、実装がネイティブのサブエージェント呼出しとは限らない。既存runnerで完結する試行を、さらに外側のLLM監視ループで包む必要なし。

## 比較条件

- 固定仕様・正解・評価器・権限境界は改善役の編集対象外。
- モデル、推論設定、入力、反復数、ツール条件を現行と候補で維持。順序・キャッシュの影響を記録。
- train、validation、最終testを分離。改善役にはtrainの記録だけを提示。独立評価役へ結論を誘導する想定正解や採用方針は渡さない。ただし決定的評価器には評価用の正解を供給。
- testは候補確定後だけ使用。最終testで改善率を主張する場合は、現行と候補の両方を同条件で測定。test結果を見て再調整する場合は、新しい独立testが必要。公開した旧testはtrainまたは回帰用へ再分類し、改善役への共有と失敗修正・回帰確認が可能。ただし、その後の再合格は独立評価として扱わない。
- 評価役の自然言語による批評は改善用の参考。固定評価器の代わりに多数決で採否を決めない。試行にばらつきがある場合は反復数・判定幅を比較前に固定し、不明な場合は測定不足として報告。
- テキスト評価と、実ファイル編集・ROS・ブラウザー操作・スキル自動発見の評価は区別。

## 実行と停止

まず現行の品質とusageを測定し、一候補を生成、同条件のvalidationで比較。既存設定の回数・時間・呼出し・総使用量上限を優先。上限がない場合は、現行測定と一候補の比較、合格候補の最終testまでを既定の有限範囲とし、追加の探索前に必要性と残資源を確認。高額・大規模な実験の予算を推測しない。

品質低下、固定仕様の逸脱、同じ失敗の反復、改善の停滞、設定上限への到達でその探索を終了。現在の最良候補・比較根拠・未解決点を報告。常駐モニターやネストした改善役による無制限の再委任は不要。サブエージェントへの再委任が必要なら主担当と分担を再調整。

ユーザーの停止指示は実行中の担当へ伝達し、今回の試行プロセスを終了。既存サービスは対象外。

## 採否とコスト

品質合格が採用の前提。平均だけでなく、固定した各ケースの品質低下も確認。品質の低い候補は短くても不採用。

usageを取得できる範囲で、指示役・改善役・実行役・評価役の入力と出力、失敗試行、再試行、統合作業を集計。cached inputは入力総数の内数として扱い、二重計上しない。取得できない担当の使用量は不明。ログ長・会話長・待機時間からトークン数を推定しない。

作業一回あたりの削減と、改善探索を含む総消費は別の値。全体usageが欠測なら、実行役の削減だけで「全体のトークン節約」と断定しない。単独と分担を比較する場合も品質・モデル・タスク条件を揃える。

探索コストの回収回数は、計測できた探索総トークンを、一回あたりの正の削減量で割った切上げ値。削減量が非正またはusageが欠測なら算出不可。モデル単価・契約枠を確認せず金額換算しない。

候補diff・品質・実測usage・時間・採否・停止理由を報告。原本への適用は依頼範囲に従い、比較だけの依頼では候補を分けて保存。
