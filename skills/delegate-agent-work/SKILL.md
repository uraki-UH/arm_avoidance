# 必要性に応じたエージェント分担

このスキルの適用時は、ユーザーの依頼範囲内で独立した仕事をサブエージェントへ委任可能。個別の呼出し確認は不要。主担当による、成果物の統合と最終検証までの継続。利用可能なツール・権限・同時実行枠の遵守。

以下は未指定時の既定方針。ユーザーが担当・役割・監視頻度を明示した場合は、その選択を優先。単独処理や通常待機へ無断で置換しない。実行環境で実現できない指定は、制約を説明して実現可能な方法を提示。

## 情報の取扱い

非公開情報の追加の外部送信は禁止。生の作業ログ・コード・テスト入力・正解・スキル本文を、改善用の別Codex CLI・API・サブエージェントへ自動転送しない。クラウドのサブエージェントもPC内処理ではない。分担前に渡す情報の範囲を確認し、非公開情報が必要な仕事は委任しない。

使用量・品質はローカルで集計し、共有可能な集計値だけを使用。集計に含めるパス・識別子・エラー本文にも非公開情報を残さない。このチャットでの応答・ツール出力もクラウドの処理対象となるため、外に出したくない生データを表示しない。スキル編集のために許可された対象の読取りと、未許可データの送信は区別。

追加のAI比較は既定で無効。将来、ユーザーが共有可能な内容・宛先・用途を明示して許可した場合だけ、その範囲で使用。非公開情報の転送許可を通常の実験依頼から推測しない。

## 利用判断

次のどれかに具体的な利点がある場合に委任。それ以外は主担当で完了。

- 独立した調査先・編集範囲が複数あり、並行して進められる場合。
- 広いコード探索の結果を、根拠付きの短い報告へ圧縮できる場合。
- 作者と異なる視点のレビューで、境界条件・参照漏れ・設計上の問題を検出できる場合。
- 固定した品質基準で候補を評価でき、改善ループへのフィードバックが必要な場合。

単独で短く終わる仕事、前工程の結果待ちだけの工程、同じファイルへの細かな交互編集、単なるビルド待ちは分担対象外。独立コマンドの並列実行には通常のツール呼出しを使用。サブエージェントは判断や文脈の分離が必要な仕事に使用。

分担時のユーザー向け更新は、役割と期待する利点を一文で説明。通常の単独処理で毎回判断表を出力する必要なし。複雑化の利益が不明なら、まず一つの限定された仕事だけ委任。

## 役割と実行

- 指示役: 主担当。目的・完了条件・分担境界・資源上限の整理、統合、最終判断。
- 実行役: 限定された調査・実装・評価試行。指定範囲内の実作業と証拠の報告。
- モニター役: 通常はログ・終了状態・評価器による計測。判断が必要な時点だけ、読み取り専用の評価役を呼出し。常駐LLMによるログ監視は不要。

全役割を常時別エージェントにする必要なし。短いレビューは主担当と評価役の二者で十分。役割名より、重複作業の削減と独立した評価を優先。

依頼に含める情報:

- 目的、期待する成果物、完了条件。
- 読取対象、編集可能なファイル、作業ディレクトリ、ビルド先。
- 固定条件、ユーザーの既存変更、関連する指示・技術上の制約。
- 検証方法、利用可能な時間・呼出し・使用量上限、終了条件。
- 戻り値: 結論、根拠となるパス・行またはログ、変更ファイル、検証結果、未解決点。

簡潔な依頼で十分な場合は新しい文脈を使用。本環境での指定は`fork_turns="none"`。会話全体の継承は、必要な文脈を切り出すと重要な条件が失われる場合に限定。モデルと推論強度は既定を継承。別モデルへの変更はユーザーまたは適用指示による明示的な指定がある場合のみ。

共有ワークスペースでは編集担当をファイル単位で分離。未コミット変更・現在の差分を依頼へ添付し、他担当の編集は上書きしない。同じビルドディレクトリで同時ビルドしない。依存工程は成果物を受け取ってから開始。再利用可能な担当には追依頼を送り、同じ範囲の探索をやり直さない。担当からの報告を読むまでは成功扱いにしない。

待機は完了通知と適切な待機ツールを使用。頻繁なログ取得・状態確認のためだけの担当は作成しない。受け取った結果を根拠へ照合し、必要な結合テストだけを実行。終了時に今回起動したプロセスの停止状態を確認。

## 長時間実行への適用

夜間・無人実行、締切付き実験、反復比較、途中保存・再開を依頼された場合は[長時間実行の条件](references/long-running.md)を読込。見積もり・実行上限・継続条件を実験前に整理。準備だけの依頼では実験やGoalを開始しない。長時間であることだけを理由にサブエージェントを増やさない。

## 指示・トークン改善への適用

指示改善・トークン節約の実測を依頼された場合だけ[改善ループ](references/improvement-loop.md)を読込。スキル作成だけの依頼ではモデル比較実験を開始しない。

判断の出典と、一般化できない点は[参考記事](references/sources.md)に記載。通常作業での記事再読込は不要。ツール仕様・モデル・価格の最新確認が必要な場合は一次資料を確認。
