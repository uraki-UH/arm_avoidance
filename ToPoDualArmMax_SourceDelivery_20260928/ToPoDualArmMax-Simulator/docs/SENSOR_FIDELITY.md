# センサー点群・色表示・近接取付の更新（2026-09-28）

## MID-360の走査

初期方式を、独自の花びら式から**Livox公式Indoor LVX2の実測方向列**へ変更しました。元記録のXYZを正規化し、時系列・点順を維持したまま現在のシーンへレイを飛ばします。実測の花びらの形・チャンネル間の方向差・点密度を使用します。旧方式は比較用に選択できます。

- 公式記録の先頭5秒、1,000,000スロット。パケット時刻間隔から5 µs/スロットを確認。
- 方向を復元できる647,615スロットを使用。残り352,385スロットはXYZ=0で方向不明のため、推測して埋めません。
- 5秒で同じ方向列をループします。無限に非反復となる機構モデルではありません。
- 元記録の欠損とmm量子化を含みます。別環境での検出率、個体差、受光ノイズ、走査中の運動歪み、IR反射率は再現しません。元記録で方向不明だった場所に新しい物体を置いても、そのスロットは無効のままです。
- 0.1秒は20,000**スロット**。有効点数とは異なります。「参照方向なし」「命中なし」「近距離除外」を別表示します。壁や天井のないシーンでは、有効点数は閉じた実験室より少なくなります。
- 点数を比較するときは積分時間を合わせてください。0.025 / 0.1 / 0.5 / 1秒を選択可能。フレーム間の点をさらに累積する表示ではありません。
- 図はセンサー上面から見た角度分布です。高さ・距離の3D点群とは別の表示です。

公式仕様は200,000 points/s、水平360°、垂直−7°〜52°です。実測方向には量子化・測定誤差等による公称画角外の値もあり、恣意的に公称境界へ移していません。実機個体と完全に同じ点群を保証するものではありません。

`extract_mid360_reference.py` が入力のLVX2接頭部から再生成します。`assets/mid360/measured-directions.json` に出典・形式・SHA-256・欠損数を記録。元ファイル全体222,540,611 bytesのうち先頭16,777,216 bytesを取得しました。

出典: [Livox公式サンプル配布](https://www.livoxtech.com/mid-360/downloads)、[MID-360仕様](https://www.livoxtech.com/mid-360/specs)、[公式通信仕様の点群・無効点の扱い](https://github.com/Livox-SDK/livox_wiki_en/blob/master/source/tutorials/new_product/mid360/livox_eth_protocol_mid360.md)。

## 腰上の近接取付

`torso_link`の子としてXYZ = **77.69 / 0 / 105 mm**、Pitch = **45°**（現在の既定値）。従来から50 mm上・17.31 mm柱側へ移動しました。base_footprint基準の原点高さは336.5 mmです。腰Yawに追従し、首の角度から独立します。

以下の隙間の検証は旧Pitch 25°での結果です。現在の45°には適用しません。実際のSTL頂点、傾斜した取付板、センサーと重なる高さにある柱の58,522三角形を確認。X方向の分離隙間は、筐体2.431 mm、取付板1.005 mmです。約1 mmを残して干渉しない配置です。取付背板は柱に接触します。これはシミュレータ内のCAD確認であり、配線コネクタ・製造公差・工具の作業空間を含む実機取付保証ではありません。

`verify_mid360_mount.py`、`MID360_MOUNT_QA.json`に再現可能な計算を保存しています。GUIの「腰上・前方45°の配置に戻す」で新しい位置へ戻せます。保存済みの旧シーンを読み込んだ場合、その位置は自動で上書きしません。

## RealSense D435i

深度は画像の各画素から1点を取得し、間引きません。1フレームの上限は848×480 = 407,040点、1280×720 = 921,600点、424×240 = 101,760点です。最短距離・視野外・左右カメラの遮蔽で無効になった画素は含めません。

初期モードを「ステレオ可視性 + Z16近似」に変更。50 mmの基線で左右の可視性を照合します。Min-Zを解像度別の195 / 280 / 105 mmへ修正しました。出典は[RealSense D400公式データシート Table 4-11](https://realsenseai.com/wp-content/uploads/2024/10/Intel-RealSense-D400-Series-Datasheet-October-2024.pdf)。実行速度はPC依存で、センサー公称fpsとは別です。

内部パラメータは公称画角からの近似です。お手元の個体に合わせるには、使用解像度の校正JSONと取付補正が必要です。`tools/export_d435i_calibration.py`とGUIの校正欄を利用できます。実IR画像でのマッチング・露光・実機欠損率・ノイズまで一致させたモデルではありません。詳細は`RGBD_README.md`。

## 両センサー共通のカラー表示

「点群の色」で**高さ／距離**を切り替えます。

- 高さ: 取得時の`base_footprint`座標のZ。床はZ=-0.14 mなので、床面からの相対高さではありません。
- 距離: 取得時のセンサー原点からのユークリッド距離。RealSenseの光学Zとは区別します。
- 低値から高値へ青紫→青→水色→緑→黄→赤。数値凡例を表示。
- 自動はそのフレーム全点の最小・最大。手動範囲はフレーム間・センサー間の色を比較するときに利用できます。範囲外の色は両端へクリップ。
- RealSenseは元のRGBにも戻せます。MID-360の反射強度は可視材質からの模擬値で、RGBセンサーではありません。

色変更は測距値・点数・座標に影響しません。元の`points.ply`・深度配列は保持し、選択中の色を持つ全点の`points_display.ply`をZIPへ追加します。`frame.json.display_color`に色の基準・範囲を保存します。表示を変えた直後でも、同じ取得フレームを再着色して保存できます。

MID-360 ZIPは`topo-mid360/3`。さらに全スロットの`slot_status.u8`と`slot_range.f32`を保存します。statusは0=有効、1=参照方向不明、2=範囲内の表面なし、3=最短距離内の遮蔽、4=ノイズによる範囲外。有効でないrangeは0です。元の有効点配列とbeam_indexは引き続き利用できます。

## 検証

`tests/baseline/SENSOR_UPDATE_QA.json`: LiDAR18項目、色計算・変換・PLY6項目。ブラウザでもLiDAR18項目、RealSense GPU11項目を実行しています。数値幾何精度は実機精度とは別です。新しい配置例は`app/examples/MID360-measured-close-mount.json`。送付物には配置JSONと数値検証の履歴を含めています。

取得ファイルを独立Pythonで再読込し、全点の座標・色・点数・無効理由・ZIP CRCを照合しました。MID-360の1秒積分は200,000スロットから38,295有効点（参照方向不明69,824、命中なし90,552、近距離除外1,329）。D435iは848×480から313,993有効点。これらは保存した7物体シーン・関節姿勢での結果であり、センサーの固定点数ではありません。これらの旧取得ZIPは開発時の履歴で、送付版には含めていません。
