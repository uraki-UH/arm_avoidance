# テーブル・物体配置とカメラ（RGB-D／単眼／ステレオ／魚眼）

## 単眼・ステレオ・魚眼カメラ

「センサ → カメラ」→ 汎用プリセット → 撮影設定 →「設定を適用」→「テーブルを見る」→「1回取得」または「連続取得」。単眼・ステレオ・魚眼それぞれでカラー／モノクロを選択可能。同じセンサタブ内の「RGB-D」とは独立した画像機能。追加の起動コマンドは不要、画面更新は再読み込み。

撮影ボタンと画像プレビューはパネル上部、取得状態・保存ボタンは画像の直下。「撮影設定」はその下に配置し、初期状態では折りたたみ。解像度や校正値を変更する場合だけ開いて適用します。

連続取得中の「1回取得」・校正適用ボタンは無効状態に固定。「停止」後、処理中の画像取得が完了すると操作可能な状態へ復帰。

- 初期解像度: 640 × 480 px
- 取得上限: 5 Hz（設定範囲: 1〜30 Hz、負荷に応じた間隔延長）
- ステレオ基線長: 60 mm
- 単眼・ステレオの初期水平画角: 70°
- 魚眼の初期有効画角: 180°（円形、範囲外は透明）
- 初期校正: 汎用の近似値。特定機種・個体の再現保証なし

### 画面からの設定

- 撮影設定: 解像度プリセット、カラー／モノクロ、取得Hz、内部描画品質
- 単眼・左／右レンズ: 任意の幅16〜1920 px・高さ16〜1080 px、焦点距離・主点、有効画角、レンズ方式、歪み係数。ステレオは左右独立
- 取付位置・左右間隔: XYZ [m]、ロール・ピッチ・ヨー [°]、左右間隔 [mm]。間隔変更時は既存の並進方向・回転を保持
- 魚眼の歪み: `k1`・`k2`・`k3`・`k4`。通常レンズの歪み: `k1`・`k2`・`p1`・`p2`・`k3`。レンズ方式の変更時は係数を0へリセット

数値を編集して「設定を適用」。解像度変更は、画素中心・画角を保持した内部パラメータのリサイズ。実機のクロップ・ビニング・解像度モード変更とは別処理。実機への一致には、使用モードの校正値を各レンズ欄へ入力。右眼の外部回転などは「詳細JSON・読込」で指定。保存済みの `calibration.json` は「JSON読込」で再利用可能。ROS YAMLやメーカー固有JSONの直接読込は未対応。

負荷調整: 「内部描画品質 → 軽量」、解像度320 × 240 px、取得Hzの引下げ。描画品質・解像度を下げた場合は細部の再現性も低下。初期値の品質・解像度は維持。

### 校正項目

- `left` / `right`: 左右別の解像度 `width`・`height` [px]、内部パラメータ `fx`・`fy`・`cx`・`cy` [px]。画素(0,0)は左上画素の中心。単眼・魚眼は `left` のみ使用。
- `color_mode`: `rgb` / `monochrome`。省略時は従来どおりカラー。モノクロはGPU上の線形RGB輝度近似、実機モノクロセンサの感度特性・IR画像の再現ではなく、転送形式は引き続きRGBA
- `distortion_model: plumb_bob`: `d = [k1, k2, p1, p2, k3]`。歪みなしは全係数0。
- `distortion_model: equidistant`: `d = [k1, k2, k3, k4]`。魚眼モードの必須方式。ステレオでも左右に指定可能。
- `max_fov_deg`: 光軸を中心とする有効円錐の全角 [°]。魚眼上限180°、ピンホール上限179°。画像の水平画角とは別。画角外・逆投影不能の画素は透明。
- `mount.translation_m` / `mount.rpy_deg`: URDFの `camera_optical_frame` から左眼への取付補正 [m / °]。光学軸はX右・Y下・Z前、回転合成は `Rz(yaw) × Ry(pitch) × Rx(roll)`。首・腰・ロボット全体の姿勢に追従。
- `right_in_left.translation_m` / `rotation`: 左眼座標で表した右眼の位置 [m]・姿勢。回転は行優先9要素、関係式は `p_left = R × p_right + t`。正のX方向が右側への基線。OpenCVの左→右変換 `R_cv, t_cv` からは `R = R_cvᵀ`、`t = -R_cvᵀ × t_cv` への変換が必要。
- `cube_size`: 内部描画の各面の辺長 [px]。256 / 512 / 1024 / 2048、初期512。出力画像の解像度とは独立、増加時はGPU負荷・メモリ増。
- `near_m` / `far_m`: 内部描画面のクリッピング距離 [m]。深度センサの測距範囲ではなく、面ごとの描画制限。

投影式の参照: [OpenCVのピンホール・歪みモデル](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)、[OpenCVの魚眼モデル](https://docs.opencv.org/4.x/db/d58/group__calib3d__fisheye.html)。スキュー、8係数以上の歪み、180°超の魚眼は対象外。

### 保存・再現範囲

「画像・校正値を保存」のZIP: `left.png`、ステレオ時の `right.png`、`calibration.json`、`frame.json`、`scene.json`。左右は同じシーン時刻の描画、同じフレーム番号・取得時刻。画像は未平行化の歪み付き画像で、モノクロ選択時は保存画像もモノクロ。`frame.json` の `optical_to_world` / `robot_to_world` は列優先16要素、並進単位m。取得時の校正・関節角度・シーンを保存し、保存操作時の姿勢への置換なし。

Nodeサーバーの保存先: `app/exports/`。既存サーバーが新しいZIP名に未対応の場合はブラウザのダウンロードへ切替。サーバーの更新反映は停止・再起動。モデル切替時は校正を保持し、連続取得を停止・旧画像を破棄。

- 再現対象: 幾何的遮蔽、左右の視差、内部・外部パラメータ、レンズ投影
- 描画方式: 画素光線に必要なキューブ面・領域のみの描画と再投影。初期単眼1面、ステレオ2面、魚眼5面。校正に応じた自動選択、魚眼の側方も撮影対象
- 共通処理: シーン行列更新は左右・全描画面で1回、CPUの上下反転コピーなし。Hz・出力方式・取付位置のみの変更時は描画資源を再利用
- 処理表示: 取得時間 [ms]、シーン描画面数。保存フレームの `num_render_pixels` は各面の描画領域の画素数合計、実際のシェーダー実行回数とは別
- 未対応: 新カメラのROS画像配信、視差からの深度推定、ステレオ平行化、露光・ノイズ・ローリングシャッター・実機固有の分光特性
- 精度制限: 内部描画と再投影の離散化。実機の画質・測距精度とは別

数値・配信テスト: `node --test tests/camera.test.mjs tests/server.test.mjs`。WebGL・UI・保存・既存RGB-Dの回帰テスト: Playwright導入環境で `node tests/camera-browser.mjs`。任意の導入先は `PLAYWRIGHT_MODULE`、Chromeパスは `CHROME_PATH` で指定。専用ブラウザ・空きポートのサーバーは試験終了時に停止。

性能比較: `CAMERA_BENCHMARK_BASELINE=/path/to/previous-camera-core.js node tests/camera-browser.mjs /tmp/camera-metrics.json 1`。Long・640 × 480 px・内部512 px、各方式で前後を交互に撮影。ウォームアップ2回＋計測20回の中央値、画素値差、描画面数をJSONへ保存。取得時間はGPU待機・通常ビューの描画を含むため、GPU・同時負荷への依存あり。

## 使い方

1. `START.cmd`で起動し、右側の **環境** タブを選びます。
2. 木製ワークテーブル／ステンレス作業台／丸テーブル／低床パレットを選択。中心位置、天板高さ、幅・奥行、Yawを調整できます。
3. 立方体／段ボール箱／ボール／円柱／ボトル／缶／マグカップ／トレーを追加します。30個まで同時配置でき、位置、Yaw、倍率、色を指定できます。
4. 配置済みの物体を選び **配置マーカー** を押すと、3D内の矢印・平面ハンドルで移動できます。**天板へ置く** で物体の底を天板Zへ戻します。複製・削除、シーンJSON保存／読込も利用できます。
5. **センサ → RGB-D → テーブルを見る → RGB-D開始** で、頭部カメラから連続取得します。**1回取得** なら静止した1フレームを取得します。 RGB-D解像度・校正を変更すると、停止中でも新しい設定で1回取得し、プレビューを更新します。切替前の画像・点群・計測値は更新待ちの間に消去されます。
6. **点群を重ねる／点群のみ** で3D表示を切り替えます。点群は取得時の世界座標に固定され、新しいフレームの取得時に更新されます。
7. 深度画像をクリックするか画素u/vを入力すると、光学座標・世界座標をm単位で確認できます。
8. **RGB-D一式** で、最後に取得した同一フレームの画像・深度・全点群・撮影時の姿勢／環境をZIPに保存します。保存先は`app/exports/`、画面のリンクからも開けます。

テーブルの位置は`base_footprint`基準。物体位置は天板中央を原点とするテーブル座標です。物体のZ=0は底面が天板上にある状態です。テーブルを動かすと物体も追従します。落下や接触力、把持の物理計算は行いません。

## 点群取得の仕組み

深度用の独立したGPU描画で、各画素に最初に見えるメッシュ表面の**光軸方向の奥行きZ [m]**をfloat32として取得します。カメラからの斜距離ではありません。アンチエイリアスによる深度の混合や点の間引きは行いません。範囲外・未検出画素は0です。近すぎる物体も遮蔽に参加し、その後ろの面が透けて取得されることはありません。

歪み補正済みピンホールモデルで、画素中心`(u,v)`から次の式で点を作ります。

```
X = (u - ppx) * Z / fx
Y = (v - ppy) * Z / fy
point_world = T_depth_optical_to_world * [X,Y,Z,1]
```

光学座標はX右・Y下・Z前、単位m。ピクセル(0,0)は左上画素の中心です。URDFの`camera_optical_frame`に取付補正を適用し、首Yaw・首Pitch・腰Yawの変化を毎回反映します。世界座標は`base_footprint`と一致します。カメラ自身の筐体、操作マーカー、グリッド、軌跡、点群表示は撮影対象から除外し、腕・テーブル・物体・床などは遮蔽に参加します。

RGBは深度と別の内部パラメータ・光学中心で描画します。深度点を`depth_to_color`でRGB座標へ変換し、RGBの深度バッファと照合して着色します。RGB視野外・RGB側で隠れた点は残したまま灰色にし、PLYの`color_valid=0`で区別します。表示色によって点のXYZを推定しません。表面のRGBはPBR描画値であり、実センサの分光応答・露光・ホワイトバランスの再現ではありません。

## 公称値と実機校正

- 初期設定はD435iの公称画角（深度87°×58°、RGB69°×42°）から算出した近似内部パラメータです。**RGB-D解像度**では、シミュレーションのRGB・深度を共通の画素数へ切り替えます。既定848×480、高密度1280×720、軽量縮小424×240を選択できます。画角を維持し、焦点距離・主点を各解像度に合わせて計算します。
- RGB・深度プレビュー上部に各画像の画素数を表示します。表示枠はパネル幅に合わせたまま、GPU描画・取得画像・保存画像の画素数が選択値へ切り替わります。詳細JSONではRGBと深度を別々の解像度にも設定できます。
- 深度基線長50 mm、depth→colorの近似並進+15 mm（光学X）、回転単位行列。URDFの光学原点を深度原点として採用し、初期取付補正は0です。
- 初期取得範囲0.195〜3 m（848×480）。1280×720は0.280 m、424×240は0.105 mから取得、Z16の単位は0.001 m。これらはJSONで変更できます。
- **幾何真値**はシーン表面のfloat32深度です。
- 初期モードの **ステレオ可視性 + Z16近似**は、50 mm離れた右カメラでも見えるかを確認し、1 mm単位に量子化します。視差マッチングや実際のIR画像生成を再現したモードではありません。

実機と座標・画角を合わせるには、使用解像度の実機内部パラメータ、depth→color外部パラメータ、取付位置・角度の校正値を **校正と精度検証** のJSONへ反映してください。ここでの回転行列は行優先の9要素です。librealsenseの生の`rotation`配列は列優先なので、転置して読み替える必要があります。`mount.translation`と`mount.rpy`はURDF光学座標から深度光学座標への変換（m、rad、URDFのZYX合成）です。

対応する画像モデルは歪み補正済み`model: none`、`coeffs: [0,0,0,0,0]`です。非ゼロ歪みを黙って無視せず、入力時に拒否します。実機校正を取得する補助スクリプト`tools/export_d435i_calibration.py`を同梱しています。実機とSDKがあるPCで任意に実行してください。この作成作業では実機への接続・動作検証は行っていません。

実機固有の測距ノイズ、欠損、マルチパス、IR投影・ステレオマッチング、透明体・鏡面材質の失敗、RGBローリングシャッター、IMU、USB遅延は再現していません。全物体は深度取得上、不透明なメッシュとして扱います。幾何真値の計算精度を、実機D435iの測距精度や同一の点群取得結果と解釈しないでください。

## 保存ファイル

| ファイル | 内容 |
|---|---|
| `points.ply` | binary little endian。全有効点のXYZ [m]、RGB、color_valid、元のpixel_index。保存時に世界／深度光学座標を選択 |
| `points_display.ply` | 選択中の高さ／距離／RGB色を持つ全点。元のpoints.plyのRGBは変更しません |
| `rgb.png` | RGBカメラの画像。深度画角への引き伸ばしなし |
| `depth.f32` | 上から行優先のfloat32 little endian、光学Z [m]、欠損0 |
| `depth.z16` | 同じ画素配列のuint16 little endian。値×depth_scale=m、欠損0 |
| `frame.json` | フレームID、時刻、単位、内部・外部パラメータ、取得時の光学→世界行列、関節角度 |
| `calibration.json` | 取得時のカメラ設定 |
| `scene.json` | 取得時のテーブルと物体。環境タブの読込でも利用可能 |
| `read_capture.py` | NumPyで深度からXYZを復元し、optical/worldのNPYを出力する例 |

点群は`depth.f32`に対応します。幾何真値モードでは、量子化した`depth.z16`から復元した点と最大0.5 depth_scaleだけZが異なります。世界変換行列はJSON内の名前どおり**列優先16要素**で保存します。外部回転3×3の行優先と混同しないでください。

## 検証と性能

**幾何精度を検証**ボタンから、実際のGPUで画素中心、非対称内部パラメータ、平面・斜面、前景遮蔽、RGBの遮蔽、最短距離、座標変換、Z16、1280×720全点数、校正値検証、PLY出力を検査できます。実行結果は画面と`document.documentElement.dataset.sensorQa`へ表示します。

作成時の11検査はPASS。斜面を独立した解析式と比較した最大Z差は0.0134 mm（許容0.05 mm）。1280×720の検査平面では921,600点。実シーンの保存ZIPもPythonで再読込し、点数、元画素番号、XYZ再構成、RGB対応、ZIPのCRCを確認しています。これは開発時の検証履歴です。送付版の検証範囲はHANDOVER.mdに記載しています。

連続取得の頻度設定は目標値です。実測Hz・取得所要時間を表示します。開発時のPCでは848×480・RGB1280×720では約6〜9 Hzを観測しました。PC/GPU、物体数、表示品質、点群表示で変動し、D435i実機のフレームレートを保証するものではありません。
