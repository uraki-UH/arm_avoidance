# テーブル・物体配置とD435i RGB-D

## 使い方

1. `START.cmd`で起動し、右側の **環境** タブを選びます。
2. 木製ワークテーブル／ステンレス作業台／丸テーブル／低床パレットを選択。中心位置、天板高さ、幅・奥行、Yawを調整できます。
3. 立方体／段ボール箱／ボール／円柱／ボトル／缶／マグカップ／トレーを追加します。30個まで同時配置でき、位置、Yaw、倍率、色を指定できます。
4. 配置済みの物体を選び **配置マーカー** を押すと、3D内の矢印・平面ハンドルで移動できます。**天板へ置く** で物体の底を天板Zへ戻します。複製・削除、シーンJSON保存／読込も利用できます。
5. **RGB-D → テーブルを見る → RGB-D開始** で、頭部カメラから連続取得します。**1回取得** なら静止した1フレームを取得します。
6. **点群を重ねる／点群のみ** で3D表示を切り替えます。点群は取得時の世界座標に固定され、連続取得中だけ更新されます。
7. 深度画像をクリックするか画素u/vを入力すると、光学座標・世界座標をm単位で確認できます。
8. **RGB-D一式** で、最後に取得した同一フレームの画像・深度・全点群・撮影時の姿勢／環境をZIPに保存します。保存先は`app/exports/`、画面のリンクからも開けます。

テーブルの位置は`base_footprint`基準。物体位置は天板中央を原点とするテーブル座標です。物体のZ=0は底面が天板上にある状態です。テーブルを動かすと物体も追従します。落下や接触力、把持の物理計算は行いません。

## 点群取得の仕組み

深度用の独立したGPU描画で、各画素に最初に見えるメッシュ表面の**光軸方向の奥行きZ [m]**をfloat32として取得します。カメラからの斜距離ではありません。アンチエイリアスによる深度の混合や点の間引きは行いません。範囲外・未検出画素は0です。近すぎる物体も遮蔽に参加し、その後ろの面が透けて取得されることはありません。

歪み補正済みピンホールモデルで、画素中心`(u,v)`から次の式で点を作ります。

```
X = (u - ppx) * Z / fx
Y = (v - ppy) * Z / fy
point_world = T_depth_optical_to_world * [X,Y,Z,1]
```

光学座標はX右・Y下・Z前、単位m。ピクセル(0,0)は左上画素の中心です。URDFの`camera_optical_frame`に取付補正を適用し、首Yaw・首Pitch・腰Yawの変化を毎回反映します。世界座標は`base_footprint`と一致します。カメラ自身の筐体、操作マーカー、グリッド、軌跡、点群表示は撮影対象から除外し、腕・テーブル・物体・床などは遮蔽に参加します。

RGBは深度と別の内部パラメータ・光学中心で描画します。深度点を`depth_to_color`でRGB座標へ変換し、RGBの深度バッファと照合して着色します。RGB視野外・RGB側で隠れた点は残したまま灰色にし、PLYの`color_valid=0`で区別します。表示色によって点のXYZを推定しません。表面のRGBはPBR描画値であり、実センサの分光応答・露光・ホワイトバランスの再現ではありません。

## 公称値と実機校正

- 初期設定はD435iの公称画角（深度87°×58°、RGB69°×42°）から算出した近似内部パラメータです。848×480／1280×720と、軽量縮小424×240を選択できます。
- RGBは1280×720。詳細JSONでは別解像度にも設定できます。
- 深度基線長50 mm、depth→colorの近似並進+15 mm（光学X）、回転単位行列。URDFの光学原点を深度原点として採用し、初期取付補正は0です。
- 初期取得範囲0.195〜3 m（848×480）。1280×720は0.280 m、424×240は0.105 mから取得、Z16の単位は0.001 m。これらはJSONで変更できます。
- **幾何真値**はシーン表面のfloat32深度です。
- 初期モードの **ステレオ可視性 + Z16近似**は、50 mm離れた右カメラでも見えるかを確認し、1 mm単位に量子化します。視差マッチングや実際のIR画像生成を再現したモードではありません。

実機と座標・画角を合わせるには、使用解像度の実機内部パラメータ、depth→color外部パラメータ、取付位置・角度の校正値を **校正と精度検証** のJSONへ反映してください。ここでの回転行列は行優先の9要素です。librealsenseの生の`rotation`配列は列優先なので、転置して読み替える必要があります。`mount.translation`と`mount.rpy`はURDF光学座標から深度光学座標への変換（m、rad、URDFのZYX合成）です。

対応する画像モデルは歪み補正済み`model: none`、`coeffs: [0,0,0,0,0]`です。非ゼロ歪みを黙って無視せず、入力時に拒否します。実機校正を取得する補助スクリプト`tools/export_d435i_calibration.py`を同梱しています。実機とSDKがあるPCで任意に実行してください。この作成作業では実機への接続・動作検証は行っていません。

実機固有の測距ノイズ、欠損、マルチパス、IR投影・ステレオマッチング、透明体・鏡面材質の失敗、RGBローリングシャッター、IMU、USB遅延は再現していません。全物体は深度取得上、不透明なメッシュとして扱います。幾何真値の計算精度を、実機D435iの測距精度や同一の点群取得結果と解釈しないでください。

## 保存ファイル

| ファイル | 内容 |
|---|---|
| `points.ply` | binary little endian。全有効点のXYZ [m]、RGB、color_valid、元のpixel_index。保存時に世界／深度光学座標を選択 |
| `points_display.ply` | 選択中の高さ／距離／RGB色を持つ全点。元のpoints.plyのRGBは変更しません |
| `rgb.png` | RGBカメラの画像。深度画角への引き伸ばしなし |
| `depth.f32` | 上から行優先のfloat32 little endian、光学Z [m]、欠損0 |
| `depth.z16` | 同じ画素配列のuint16 little endian。値×depth_scale=m、欠損0 |
| `frame.json` | フレームID、時刻、単位、内部・外部パラメータ、取得時の光学→世界行列、関節角度 |
| `calibration.json` | 取得時のカメラ設定 |
| `scene.json` | 取得時のテーブルと物体。環境タブの読込でも利用可能 |
| `read_capture.py` | NumPyで深度からXYZを復元し、optical/worldのNPYを出力する例 |

点群は`depth.f32`に対応します。幾何真値モードでは、量子化した`depth.z16`から復元した点と最大0.5 depth_scaleだけZが異なります。世界変換行列はJSON内の名前どおり**列優先16要素**で保存します。外部回転3×3の行優先と混同しないでください。

## 検証と性能

**幾何精度を検証**ボタンから、実際のGPUで画素中心、非対称内部パラメータ、平面・斜面、前景遮蔽、RGBの遮蔽、最短距離、座標変換、Z16、1280×720全点数、校正値検証、PLY出力を検査できます。実行結果は画面と`document.documentElement.dataset.sensorQa`へ表示します。

作成時の11検査はPASS。斜面を独立した解析式と比較した最大Z差は0.0134 mm（許容0.05 mm）。1280×720の検査平面では921,600点。実シーンの保存ZIPもPythonで再読込し、点数、元画素番号、XYZ再構成、RGB対応、ZIPのCRCを確認しています。これは開発時の検証履歴です。送付版の検証範囲はHANDOVER.mdに記載しています。

連続取得の頻度設定は目標値です。実測Hz・取得所要時間を表示します。開発時のPCでは848×480・RGB1280×720では約6〜9 Hzを観測しました。PC/GPU、物体数、表示品質、点群表示で変動し、D435i実機のフレームレートを保証するものではありません。
