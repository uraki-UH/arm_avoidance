# OSCBF回避オプション

## 要約

- 対象: 双腕SimulatorのMuJoCo関節動力学。標準／Long。
- 上流: https://github.com/StanfordASL/oscbf 。固定コミットは `vendor/UPSTREAM`。
- ライセンス: `vendor/LICENSE.oscbf`。上流Pythonソースは未改変で同梱。
- 方式: 公式 `OSCBFVelocityConfig` とCBFpyの速度フィルタ。
- MuJoCoの関節情報・慣性行列・両TCPヤコビアンに接続したアダプタ。
- 作業空間と冗長自由度の目的関数は双腕向けに正則化。
- 障害物距離と勾配を各更新時に線形化し、関節速度・位置制約とともにQPへ入力。
- 回避後の速度へ慣性補償付き制御で追従。URDFのトルク上限はMuJoCoが適用。
- 公式Franka用衝突モデル・PyBulletデモのそのままの移植ではない。
- 既定は回避なし。OSCBF未選択時はJAXの読込・回避計算なし。

導入はDocker内で1回実行:

```bash
cd /ros2_ws/src/ToPoDualArmMax_SourceDelivery_20260928/ToPoDualArmMax-Simulator
bash integrations/ros2/oscbf_avoidance/install.sh
```

ブラウザを再読み込みし、「物理 → 回避モジュール → OSCBF」を選択して「物理を開始」。
ロボットは「関節動力学」、姿勢の入力元は「シミュレータ操作」が必要。
障害物は環境タブで追加し、固定・動的・姿勢指定など物理モデルを有効化。
物理なしの物体、ROS点群・GNGレイヤーはこのフィルタの入力外。
ホーム姿勢などから既に物体に深く侵入している場合は開始失敗の可能性あり。
初回はJAXコンパイルによる待ち時間あり。CPU版を使用。
依存はこのフォルダの `.deps/` に隔離し、Git対象外。通常のPython環境は変更しない。

設定は `defaults.json`。変更後は物理を停止して再開始。

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| clearance | 0.06 m | 外接球と環境形状の離隔余裕 |
| max_joint_velocity | 0.3 | 回転rad/s・直動m/s。URDF上限との小さい方 |
| max_constraints | 64 | 近接形状対の上限 |

- ロボットはMuJoCo各衝突形状の外接球、環境は箱・床の解析的距離。
- 実メッシュより保守的な近似。狭い隙間を通れない場合あり。
- メッシュ間距離APIで離隔中の距離0と最近接点の不整合を確認したため、回避には不使用。
- 物理の接触計算は既存のMuJoCo衝突形状を維持。
- 自己衝突・左右腕間回避、LiDAR/GNG入力、実機制御への接続は未対応。
- 動的物体はMuJoCo速度で一次予測。姿勢指定物体の瞬間移動は予測対象外。
- 速度CBFとトルク制限付き追従の組合せ。トルク飽和・離散更新を含む安全保証はなし。
- 解が非有限、制約違反、形状対数超過の場合は物理セッション停止。回避なしへの自動復帰なし。
- 物理停止はシミュレータ内の停止。実機の停止指令ではない。
- OSCBFは10 msのシミュレーション更新ごとに計算。物理は2 ms×5ステップ。
- 状態欄の時間はフィルタ更新の実時間。実時間周期の保証なし。

## 条件・検証

```bash
python3 integrations/ros2/oscbf_avoidance/test_filter.py
```

標準／Longの左肩目標1.2 rad、途中姿勢のTCP位置に辺5 cmの固定箱を配置。
6秒のシミュレーションで回避なしとの接触数比較、外接球の離隔、トルク上限を検証。
続いて障害物を移動し、3秒で目標方向への追従再開を検証。
接触数は各更新時の接触点数の累積で、衝突イベント数ではない。
移動障害物・自己衝突・実機・複雑な多障害物環境の検証は未実施。

2026-10-09、CPU実測（初回JITを除外、10 msシミュレーション更新あたり）:

| モデル | 回避OFF／ONの平均計算時間 | OFF／ONの累積接触点数 |
| --- | --- | --- |
| Long | 1.41／7.02 ms | 571／0 |
| 標準 | 1.44／6.84 ms | 1142／0 |

両モデルで離隔約0.06 m、トルク上限維持、障害物移動後の追従再開を確認。
回避ONは速度追従制御への切替も含むため、計算時間差はQP単体の費用ではない。
