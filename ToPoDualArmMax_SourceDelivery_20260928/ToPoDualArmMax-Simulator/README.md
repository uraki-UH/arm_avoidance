# ToPoDualArm-Max Simulator — ソースコード送付版

標準（無印）・Long対応 / 送付版 1.0.0 / 2026-09-28

提供URDF・STLを用いたブラウザ型シミュレータです。編集可能なソース、両モデルの元データ、描画キャッシュ、依存ライブラリを同梱しています。Codex・送付元PCのアカウント・開発フォルダーは不要です。

## 最初に起動する

必要なもの: **Node.js 22以上**とWebGL 2対応のブラウザ（Chrome / Edge等）。Node.js 24.19.0で検証しています。Node.jsは https://nodejs.org/ から導入し、`node --version` が実行できる状態にしてください。ソースからの初回起動では、以下のUIビルドが必要です。`npm run build`はThree.js本体と内部依存も`app/vendor/three/build/`へ配置します。生成済みの`app/generated/`とThree.js本体の両方を含む配布物は、Node.jsだけで起動できます。

```bash
npm ci
npm run build
```

共有ソースはワークスペースの `ToPoFuzzy-Viewer/frontend/src/` と `libs/ros_visualization_web/`。再ビルド時はこの配置も必要です。Viewer側でのnpmインストールや画面起動は不要です。

### Windows

1. ZIPをすべて展開する。ZIPの中から直接実行しないでください。
2. `START.cmd` をダブルクリックする。
3. 自動で開いたブラウザを使用する。複数のブラウザやタブから同じURLへ接続できます。

既定ポートは8877です。別フォルダーのシミュレータなどが使用中なら、8878～8892から空きを選びます。同じ送付フォルダーからの再実行はサーバーを共用します。起動ログは `runtime/` に保存されます。

```powershell
# 別のポートから探す / ブラウザを開かずに起動
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Simulator.ps1 -Port 9000 -NoBrowser
# この送付フォルダーが起動したサーバーだけを停止。起動時のポートを指定
powershell -NoProfile -ExecutionPolicy Bypass -File .\Stop-Simulator.ps1 -Port 9000
```

### Windows / Linux / macOS共通

このREADMEのあるフォルダーで実行します。

```text
node app/server.mjs
```

表示された `http://127.0.0.1:8877/` を開きます。終了は端末でCtrl+C。`npm start` も同じ動作です。Linux / macOSでは `sh start.sh` でも起動できます。ポートを変える場合はPowerShellで `$env:PORT='9000'`、Linux / macOSでは `PORT=9000 sh start.sh` とします。

`index.html` の直接オープン（file://）は対応しません。起動後、標準のシミュレータ機能は外部サイトへの通信なしで動作します。サーバーはローカルPCの127.0.0.1にのみ待ち受けます。

### 描画が重い場合（受領環境での調整）

視点の慣性（OrbitControls damping）を無効化し、マウス操作に直接追従させています。反映にはページ再読み込みが必要です。

初期描画品質を「標準」に変更しています。SSAOを無効にし、画面のピクセル比を1に設定。標準品質では画面全体の後処理用中間バッファを経由せず直接描画し、描画バッファの常時保持も無効化。PNG保存は保存直前の再描画で対応。高精細表示は「シーンと描画 → 描画品質」で選べます。RGB-Dの取得解像度・点群数・校正値は変更しません。

GPU描画・ROS連携をまとめて起動する場合は、ホスト側のワークスペースのルートで以下を実行します。起動済みのDockerサービス `gng_cpu` が必要です。

```bash
bash scripts/open_dual_arm_nvidia.sh
```

DockerfileでNode.js 22・MuJoCo・OSQPと、ロックファイルに対応するシミュレータのnpm依存を取得します。依存キャッシュはソースのマウント外に保持します。`app/generated/ros-results.js`、`app/vendor/three/build/three.module.js`、`three.core.js`のいずれかがない場合、`start_ros.sh`がキャッシュ優先で`npm ci`とUIビルドを実行します。同時起動時の重複ビルドは抑止します。必要ファイルが揃っている場合は再ビルドしないため、UIソース更新後はアプリのルートで`npm ci && npm run build`を実行してください。起動前にも不足ファイルを検査し、不足時はファイル名とビルドコマンドを表示します。

Dockerfileの更新は既存コンテナへ自動反映されません。ワークスペースルートの`docker compose build gng_cpu`でイメージを更新し、コンテナ内の作業を終了できる時点で`docker compose up -d --no-deps gng_cpu`を実行してください。コンテナ再作成時は、その中で動作中のノードも停止します。

専用ランチャーはURL入力不要、既定はLongです。標準モデルは末尾に `standard` を指定。topofuzzy viewerと別のChromeプロファイル、X11、1440×1000の初期ウィンドウで開きます。サーバーとROS/物理ブリッジは未起動ならDocker内で背景起動し、応答確認後にブラウザを開きます。既存サービスは再利用します。ブラウザを閉じてもバックエンドは継続し、停止コマンドとログの場所は新規起動時に表示します。ブラウザだけを開く場合は `enable_backend=0` を指定します。既存の汎用ランチャーも引き続き利用可能で、Markdownリンク形式の引数はURLに補正します。

NVIDIAが利用可能ならNVIDIA、利用不能なら理由を表示してMesa経由の描画へ切り替えます。この環境ではIntel GPUによるWebGL描画とMID-360取得を確認済みです。`Driver/library version mismatch` はホストのドライバとライブラリの不一致で、NVIDIAへの復帰には保存後のホスト再起動が必要です。NVIDIAのみを要求する場合は `viewer_gpu=nvidia bash scripts/open_dual_arm_nvidia.sh long` を使用します。

RGB-D連続取得では、計測・表示処理にかかった時間と同じ長さの休止を確保し、画面操作の時間を残します。指定Hzは上限であり、負荷に応じて取得頻度が下がります。非表示点群の色計算も省略。解像度・点数は維持します。VM・AI側の送信頻度制御は別処理です。変更はページ再読み込みで反映されます。

RGB-D取得中に表示用シャドウマップを更新しないよう修正しました。センサ用に物体を非表示化した状態の影が通常画面へ残る問題への対処です。反映にはページ再読み込みが必要です。

2026-10-01の標準モデル・静止画面ではRGB-D取得前後4回の画素差0を確認。ユーザー画面のちらつきとの同一原因や体感改善は未確認です。画素計算・プレビュー描画・GPU負荷は残るため、非同期化だけで操作の引っかかりが解消する保証はありません。動的場面での体感改善は未検証です。

深度画像はGPUが対応する読出し形式を自動選択します。単一成分floatに対応するGPUではR32Fを使用し、非対応GPUではfloat32のビット列をRGBA8へ格納します。どちらも1画素4バイトで、格納形式による追加の量子化・間引きはありません。従来のRGBA float読出しが必要なGPUでは転送量を1/4に抑えられます。

RGB-DのGPU読み出しは、複数画像を同じ転送バッファへ集約し、全画像の転送完了後に1回だけCPUへコピーします。バッファを再利用し、取得ごとのGPU対応形式の問い合わせを省略します。完了待ち中も画面更新を継続します。非表示タブのプレビュー描画は保留し、再表示時に最新フレームを反映します。二重取得を防止し、モデル・校正変更前の取得結果は破棄します。開発用 `simulator.rgbd.capture()` の戻り値はPromiseのため `await` が必要です。低水準の `sensor.capture()` は既定で同期処理を維持しています。

GBMの `Permission denied` は、この環境ではNVIDIA描画が正常な場合にも発生しました。警告の有無だけでGPU使用・停止原因を判断しないでください。起動スクリプトは検証済みの `gl-egl` 経路を維持しています。

受領後の変更により、元の `MANIFEST.json` に対する検証では `app/app.js`、`app/index.html`、`app/rgbd-ui.js`、`app/rgbd-core.js`、`app/vm-ai.js`、`app/qa-models.js`、本READMEなどが変更済みとして表示されます。点群送信・物体編集の追加ファイルも元のMANIFESTの検証対象外です。

## 操作と収録機能

右側の操作タブは「ロボット／環境／センサ／物理／VM・AI／ROS2連携」。RGB-D・カメラ・LiDARは「センサ」内の子タブ、MuJoCoの開始・停止・物理設定は「物理」に配置。タブ移動だけでは設定値や取得状態をリセットせず、最後に選んだセンサ子タブを保持します。変更の反映はページ再読み込み。

- 上部タブで標準 / Longを切り替え。URL末尾 `?model=standard` / `?model=long` でも指定できます。
- 手先マーカーの移動・回転、位置/姿勢IK、グリッパー、首2軸、腰Yaw。
- テーブル・物体・車両の配置、寸法、位置・姿勢・色の変更。
- D435i RGB-D / MID-360点群取得、距離・高さの着色、撮影データ保存。
- 単眼・ステレオ・魚眼のカラー／モノクロ画像取得。画面での解像度・歪み・描画品質設定、校正JSON読込、画像・撮影姿勢の保存。[カメラ設定](docs/RGBD_README.md#単眼ステレオ魚眼カメラ)。
- ポーズ・動作シーケンス・シーンの保存。Node版の保存先は `app/exports/`（初回保存時に作成）。

モデル切り替え時は環境・視点・センサ設定を保持し、姿勢とシーケンスをモデル別に保持します。ページ再読み込みを越えて残す場合はJSON保存を使用してください。モデル識別のない従来のポーズJSONはLong用として読み込みます。

これは運動学・描画・幾何センサのシミュレータです。物理的な接触力、動力学、衝突回避や実機への制御指令は実装していません。センサの再現範囲は [センサ仕様](docs/SENSOR_FIDELITY.md) を参照してください。

「ROS 2連携 → ROS Scene Layers」の初回表示時に、既定の `ws://127.0.0.1:9001/observe` へ自動接続し、Topics一覧を取得します。
接続中は `Online` と表示し、クリックで切断します。手動切断後は `Offline` をクリックして再接続します。
接続先と表示基準フレームは「接続・座標設定」を開いて変更できます。接続先の変更時は新しいサーバーへ自動接続します。
`Topics` のチェックボックスで見たい入力を選択し、右端の更新アイコンで一覧を再取得します。ROS由来のロボットも `Robot · <名前>` として同じ一覧に表示し、初期状態は未選択です。
ONで購読・表示、OFFでこの画面のScene Layersと3D表示から除去します。`Scene Layers` の削除ボタンも選択解除と連動し、目アイコンは表示だけの切替です。再チェックで最新データを表示します。
ロボットはURDFと姿勢を1件として管理し、未選択中もモデルと最新姿勢を保持します。Simulator本体のロボット・物理演算・制御はROS表示の選択に影響されません。
ToPoFuzzy-Viewerの描画部品・設定UIを共用しており、別のViewer画面は不要です。
チェック済みでもTFが未解決の場合はフレーム名を表示します。環境地図は必要に応じて `map を基準に表示` を使用してください。
広い地図で点が小さい場合は対象レイヤーの色設定（Node／Edge）から `Node Size`／`Edge Width` を調整できます。

- GNG・軌道・平面／非平面クラスタ、境界／把持ラベル、法線・速度矢印・共分散／可操作性楕円体。
- PointCloud2とヒートマップ、MarkerArray／PoseArray、ボクセル。
- ROSロボットの外観・衝突形状・姿勢候補・可操作性表示。
- 候補枠の選択と独立3D詳細、モデル照合、表示色・透明度・ラベル・クリッピング・監視領域・ローカルメッシュ。

データに該当属性がある場合に表示できます。各形式・選択条件はViewerと共通です。
接続・起動手順は[ROS連携](integrations/ros2/README.md#ros処理結果の表示専用接続)を参照してください。

UIはReact＋TypeScriptで、ROSパネルを開いたときだけ遅延読み込みします。

ROSの重ね描画はセンサー撮影から除外し、切断で受信データとTFを消去します。
独立3D詳細を開いた間だけ追加のCanvasを使用します。新規TSはstrict型検査対象です。

## ROS 2への点群送信・物体編集

サーバーとROSブリッジをまとめて起動する場合は、Docker内のこのフォルダーで `bash start_ros.sh`。ホストからの一括起動コマンドは[ROS起動手順](integrations/ros2/README.md#サーバーとrosブリッジの一括起動)を参照してください。

再読み込み後の「ROS2連携」タブで、RGB-D全体／MID-360／対象物体の完全表面／対象物体の遮蔽付きRGB-Dの送信トピックをチェックで複数選択できます。取得とHz設定はセンサ側、対象物体の点群生成は「環境 → 物体点群の取得」で操作します。
MID-360は「センサ → LiDAR」で有効化し、取付位置・姿勢・積分時間・連続取得Hzを設定して取得を開始。「ROS2連携」は新しい取得結果を `/sim/lidar/points` に送信します。
Longの胸部MID-360: STEP由来の45°ブラケット・4色の筐体。ページ再読み込みで反映、取得が無効でも本体を表示。保存済みの旧配置は「ロボットの既定取付位置に戻す」で更新。標準モデルは従来の簡易取付。実機の計測原点は未校正。[配置・制限](docs/SENSOR_FIDELITY.md#腰上の近接取付)。
RGB-D全体では、深度画像・CameraInfo・色付き画素対応PointCloud2も同時送信可能（既定ON）。更新後はブリッジも再起動してください。
送信には独立ブリッジ `integrations/ros2/pointcloud_bridge.py` を起動し、送信先を指定してください。
[起動・トピック・制限](integrations/ros2/README.md#独立した点群送信) を参照。GNG・FVGの処理結果を待たずに送信できます。

「環境 → 外部環境」で「街並み：Littlest Tokyo」を選択し、「環境を読み込む」で追加。「環境全体を表示」で視点を合わせます。「なし」を選んで読み込むと環境だけを解除。ロボット・作業台・既存物体は保持し、初期状態での自動読込はありません。
街並みは約4.1 MBのローカルGLBで、取得後の外部通信は不要です。元のY-upをZ-upへ変換し、水平最大寸法12 m・足元Z=-0.14 m・左端X=1.5 mへ配置。ミニチュア調の試験用縮尺であり、実寸の都市データではありません。
RGB-D・LiDARは環境メッシュも計測対象に含みます。環境の物理衝突・建物単位の編集・アニメーションは未対応。環境の選択は「シーン保存／読込」の`environment_asset`に保持し、この項目のない従来JSONは外部環境なしで復元します。任意GLBのファイル取込ではなく、同梱サンプルの選択機能です。
作者はGlen Fox / glenatron、ライセンスはCC BY 4.0。[素材の出典・加工内容](app/assets/environments/littlest_tokyo/ATTRIBUTION.md)を参照。動作検証は`node tests/environment-assets.browser.mjs`（Chromeが必要）。

「環境」の追加位置で座標系（テーブル／world）とXYZ［mm］を指定し、物体・車両を追加します。
指定値は物体原点の位置であり、自動接地ではありません。追加後は既存の位置欄で変更可能です。
3D上の物体はCtrl＋クリック（Macでは⌘＋クリックも可）で選択を追加・解除できます。選択中の物体を右クリックして「選択した○個を削除」、またはDeleteキーで一括削除。入力欄の編集中はDeleteで物体を削除しません。通常クリックは単体選択、右ドラッグは視点操作です。複数選択中の位置・形状編集は無効で、各物体に選択枠を表示します。

物体を右クリックし、「物理を有効にする」のチェックでON/OFFを切り替えます。初回ONは動的（落下・接触）。同じ画面内でOFF→ONに戻す場合は直前のモード・拘束を復元します。「詳細設定」を開くと固定／姿勢指定／ヒンジ／スライドなどを選択して適用できます。複数選択時は一括適用し、各物体の質量は保持。「物理設定を開く」は右クリックした物体を単体選択して「物理」タブへ移動。質量や拘束軸・範囲の詳細設定はこのタブで変更します。

ロボットの表示メッシュにカーソルを合わせると、クリック前から全体の水色BBoxを表示します。カーソルを外すとホバー枠は消え、通常物体に合わせると黄色の枠へ切替。右クリックで選択・物理メニューを開き、「関節動力学を有効にする」のチェックで切替。OFFは姿勢指定（接触のみ）で、接触まで無効にはなりません。モード一覧は「詳細設定」内に配置。リンク単位ではなくロボット全体への設定です。「物理設定を開く」でロボットの設定欄へ移動。物体の選択は解除し、ロボットには削除メニューを表示しません。モデル切替後の古い対象への適用は拒否します。

モード変更時は実行中の物理を停止し、次の「物理を開始」で反映。設定変更だけでは自動開始しません。物体への同じモードの再適用では拘束を保持し、別モードへの変更では旧拘束を解除します。ロボットのモード変更では関節固定・自己接触の設定を保持します。
「テーブルを見る」、ポーズ再生、VM・AIの動作、プリセット移動は物理OFFならブラウザ単独で使用可能です。物理ブリッジへの接続や自動起動は行いません。「物理を開始」した場合のみMuJoCo経由で動作し、物理時間に合わせて指令を進めます。接触させたい物体は個別に物理ONが必要です。

### 物体のホバー選択・ドラッグ配置

ページ再読み込み後、3D画面左下のコンパクトな物体操作バーを利用できます。

- ホバー: 手前の物体に黄色のBBox。左クリックで選択。
- 選択解除: 3D画面で物体以外を左クリック、または`Esc`。複数選択・BBox・配置プレビュー・右クリックメニューをまとめて解除。入力欄の編集中とダイアログ表示中は選択解除を抑止（右クリックメニュー内の`Esc`は解除）。
- 左ドラッグ: 床・水平な天板・物体上面へ半透明の目標を表示。物理実行中も指定・回転可能。元物体は物理姿勢に追従、目標のworld座標は保持。
- `T` / `Shift+T`: 候補をworldのZ軸まわりに±15°回転。ボタンでも回転可能。ドラッグ中のホイールでもYawを±15°、Shift併用で±5°回転。この間はカメラズームを抑止。
- `Enter` /「確定」: 直接配置（物理OFF時のみ）。`Esc`: 候補と選択を解除。「×」: 候補だけを破棄。実行制限はボタンの補足表示へ集約。メッセージは無効な目標、または実行を試みた場合の制約のみ。
- 何もない場所の左ドラッグ: 従来の視点回転。ドラッグでは選択を維持。既存の配置マーカー操作中はマーカー優先。

プレビューは表示専用overlayに配置し、点群・深度画像には含めません。確定後は通常のシーン物体として反映。元物体の削除・非表示・手動配置変更、配置面なしは確定不可。物理による元姿勢の更新は許容。位置・寸法欄など既存の配置編集も併用できます。

「直接配置」は編集操作であり、重なり・支持安定性・ロボット到達性の保証なし。「把持して移動」「押して移動・回転」は目標のプレビューのみで、実行ボタンは「未接続」で無効。目標指定のための物理停止は不要。IK・把持・接触・衝突の可否判定やROSへのタスク送信は未実装で、成功扱いや物体の自動追従なし。

検証: このディレクトリで `node tests/object-interaction.browser.mjs`。Node.js 22以降とChromeが必要、別実行ファイルは`CHROME_BIN`で指定。専用サーバー・専用ブラウザによるホバー、ドラッグ、回転、確定、取消、親座標系、実行不可、模擬物理フレーム受信中の目標保持の試験。試験終了時に専用プロセスを停止し、プロファイルを削除。

## 受領時の確認

```text
node tools/verify.mjs
node --test tests/server.test.mjs
```

最初のコマンドは `MANIFEST.json` のSHA-256と全収録ファイルを照合します。ソースを編集・キャッシュを再生成した後は、意図した変更も差異として表示します。HTTPテストは空きポートで起動し、終了時にテスト用サーバーと保存データを片付けます。

ブラウザ検証は起動URLの末尾を `/?model=standard&qa=models` に変更します。テスト中は姿勢と表示を操作するため、作業中の画面とは別タブで開いてください。結果はページ内の非表示 `#model-qa-results` とコンソールに出力します。

## VM・AiS-GNG-FVGについて

連携用フロントエンド・ROS 2 HTTPブリッジ・形式解析コードは含みます。**AiS-GNG-FVG本体、学習用バイナリ、FVG observer、ROS独自メッセージパッケージ、VMイメージは別途必要**です。通常のシミュレータはこれらなしで起動できます。[VM連携の導入手順](integrations/ros2/README.md) を参照してください。
