# 局所平面クラスタを利用した上方把持候補推定

GNG平面クラスタからの幾何候補生成。実機把持成功の報告ではない。

## 1. 要旨

**GNGの局所平面クラスタを把持対象領域の候補とし、水平投影した領域サイズと隣接平面からの距離によって候補を絞り、上方から進入するTCP位置・姿勢を生成する方式。**

- 入力はGNGグラフと局所平面クラスタ。対象物全体の認識やテンプレート登録は不要。
- 平面クラスタ単位の評価による、探索対象の削減。
- 各クラスタの単独候補に加え、明示的に有効化した場合は接続・合算寸法による平面組合せ候補を生成。近くの壁・床の無条件な一括統合なし。
- 出力は幾何条件を満たす「把持候補」。指接触、干渉のない進入、摩擦、到達性の成立保証は対象外。

「上方」は候補TCPの進入方向の制約に加え、起点平面の法線と`up_axis`の傾斜角で判定。法線の符号反転を許容し、C++既定の許容角は25度。現在の`ToPoDualArm.yaml`は許容角90度・平面組合せON・上方障害物判定OFF。非平面付属抽出は参照面方式で固定。ゼロ・不正法線の除外は維持。

## 2. 入出力と処理範囲

```text
観測点群
   |
GNG学習・局所平面クラスタ生成（前段）
   |
   +-- /topological_map : ノード位置、エッジ
   +-- /plane_clusters : 所属ノード添字、重心、法線
   |
   v
本方式: 入力整合確認
   -> クラスタごとの水平投影・2D凸包・回転を考慮した開口包含判定
   -> GNGエッジからクラスタ間の隣接関係を抽出
   -> 隣接平面からの距離判定
   -> TCP位置・姿勢の生成
   -> 局所非平面成分の開口包含・上方進入障害物の判定
   -> 高さ優先の並べ替え・件数制限
   |
   +-- 候補GraspCandidateArray（ID・姿勢・到達性状態）
   +-- 面積比・診断summary
   +-- Viewerが同じ候補IDの矢印を状態に応じて色分け
```

平面クラスタの分割・成長・統合は前段処理。本方式は受信した分割結果を利用し、再クラスタリングしない。CPU版GNGの直接クラスタ出力と接続可能。ボクセル方式の把持照合や軌道生成とは独立した経路。

| 入力 | 利用内容 |
| --- | --- |
| `TopologicalMap.nodes` | 位置、nonplane_component_id、boundary_evidence |
| `TopologicalMap.edges` | 2要素一組のエッジ端点添字 |
| `PlaneCluster.node_indices` | 同一更新のノード配列に対する所属添字。永続ノードIDではない |
| `PlaneCluster.centroid` | 候補重心と隣接平面の基準点 |
| `PlaneCluster.normal` | 上面傾斜角・隣接平面までの距離計算 |
| `frame_number`, `header.frame_id` | グラフとクラスタの整合確認 |

クラスタの `position_covariance`、`extent_u/v`、`area`、`boundary`、`planarity` は、この候補推定器では直接利用しない。投影矩形は所属ノードから再計算。

## 3. アルゴリズム

### 3.1 座標系と入力確認

正規化済みの上方向ベクトルを $\mathbf{w}$ とし、これと直交する単位基底を $\mathbf{u},\mathbf{v}$ とする。既定の `up_axis=[0,0,1]` では、それぞれ候補評価座標系のX、Y、Z軸に対応。

ROSノードは、グラフとクラスタの `frame_number`、`header.frame_id`、`header.stamp` が一致した組だけを処理する。`candidate_frame` が空文字なら入力座標系のまま評価・配信し、TF取得も行わない。値を設定した場合だけ、グラフ時刻のTFで両方を `candidate_frame` に変換してから評価する。`up_axis`、平面法線の傾斜、TCP位置・姿勢はすべてこの評価座標系で扱う。

外部センサの固定TFは把持推定の責務ではない。ロボット基準の評価が必要なときは、`candidate_frame` を `ToPoDualArm/base_link` に設定し、URDFのfixed jointまたは実機bringupから対応する外部センサTFを配信する。TF がない、または入力時刻がゼロで座標変換が必要な場合は、誤った座標で候補を出さず、候補・スコアを空配列として配信し、summary の `status` を `tf_unavailable` とする。これにより以前の候補が残留しない。同じグラフ番号・時刻の成功済み入力は再処理しない。

クラスタごとに重心の有限性と所属添字の範囲を確認し、所属ノード数を判定。矩形計算時には各ノード位置の有限性も確認。ノード数不足は `rejected_small_region`、不正データ・ゼロ法線は `rejected_invalid_region` に集計。正規化法線と上方向の内積絶対値が`cos(max_surface_tilt_deg)`に満たない面は`rejected_surface_tilt`として棄却。棄却面も隣接平面・障害物の根拠として維持。

### 3.2 水平投影と2D凸包

クラスタ $C_i$ の所属ノード位置 $\mathbf{p}_k$ を水平面へ投影:

$$
\mathbf{q}_k=
\begin{bmatrix}\mathbf{u}^{\mathsf T}\mathbf{p}_k\\\mathbf{v}^{\mathsf T}\mathbf{p}_k\end{bmatrix},
\qquad
h_i=\max_{k\in C_i}\mathbf{w}^{\mathsf T}\mathbf{p}_k.
$$

投影点を辞書順に整列し、重複を除去した単調鎖法で反時計回りの凸包を構成。内点と辺上の中間点は、任意方向の投影最小・最大に影響しないため保持不要。点・線分への退化も処理対象。

角度 $\theta\in[0,\pi)$ に対応する2本の直交軸:

$$
\mathbf{a}=(\cos\theta,\sin\theta)^{\mathsf T},
\quad
\mathbf{b}=(-\sin\theta,\cos\theta)^{\mathsf T}.
$$

PCAやノードの入力残差共分散は使用しない。同じ凸包であれば、内部の点密度や重複数によらず同じ外形判定。

### 3.3 投影外接矩形とハンドへの包含判定

各軸方向の射影値の最小・最大から外接矩形を構成。例えば軸 $\mathbf{a}$ について:

$$
\ell_a=\min_k\mathbf{a}^{\mathsf T}\mathbf{q}_k,
\quad r_a=\max_k\mathbf{a}^{\mathsf T}\mathbf{q}_k,
\quad L_a=r_a-\ell_a.
$$

軸 $\mathbf{b}$ についても同様に $\ell_b,r_b,L_b$ を算出。矩形中心は:

$$
\mathbf{c}_{uv}=\mathbf{a}\frac{\ell_a+r_a}{2}
                 +\mathbf{b}\frac{\ell_b+r_b}{2}.
$$

把持面寸法を $G_x,G_y$ とすると、補正なしの使用可能寸法は:

$$
U_x=G_x,\qquad U_y=G_y.
$$

採用可能なサイズ条件:

$$
\exists\theta\in[0,\pi):\quad L_a(\theta)\le U_x\ \land\ L_b(\theta)\le U_y.
$$

凸包の各辺の方向と、それに直交する方向を境に角度区間を分割。区間内では4方向の支持頂点が固定され、各外接幅は `a*cos(theta) + b*sin(theta)` の形になる。非負の幅は区間内で凹関数なので、`max(L_a/U_x, L_b/U_y)` の最小点は区間端点または2つの寸法比の交点。この有限個の角度を評価することで、一定刻みの角度走査なしで包含可能な向きの有無を判定。90度入れ替えも探索範囲内。

包含可能な評価角度の中で外接面積の小さい向きを採用し、同等なら小さい角度を優先。全連続角度についての制約付き最小面積解を保証する方式ではない。不適合なら単独候補としては `rejected_oversize_region`。比較時にはdoubleの丸め誤差だけを許容し、実寸余白の追加なし。

`enable_plane_combinations=true`では、隣接平面を追加するたびに現在の凸包と追加先の凸包を合算し、向き・中心・寸法を再評価。最初に採用した軸への固定なし。直接接続と非平面連結成分経由の接続が対象。起点には最低ノード数・傾斜角の条件を適用するが、追加先には同じ起点条件を要求せず、小平面や側面も合算対象。空所属・不正座標・不正法線は除外。単独候補と複合候補は別候補として併存し、全組合せの総当たり探索なし。`rejected_small_region`等は起点判定の棄却数であり、その平面が複合候補に含まれないことを意味しない。

- 最小面積矩形1つだけや凸包辺に平行な矩形だけで判断せず、開口の縦横比に応じた辺間の向きも評価。
- 判定は面積だけでなく、2方向の寸法それぞれに対する包含条件。
- 観測外形と指定の把持可能寸法との直接比較。固定余白・外形の膨張補正なし。
- 凸包内部の穴や未観測部分を占有済みとは扱わない。凸包の用途は平面ノード集合の矩形包含判定のみ。

### 3.4 GNGエッジに基づくクラスタ隣接関係

各ノード添字から所属クラスタへの対応表を作成し、GNGエッジを一度走査。異なるクラスタに属する端点間のエッジが1本でもあれば、クラスタ間の無向隣接関係を登録。重複する関係は集合で除去。

- 距離近傍探索やクラスタ全対比較は不要。
- 非平面連結成分を介した平面間の接続も隣接関係へ登録。不正座標と`BOUNDARY_FREE_SPACE`の非平面ノードを経由した接続は除外。
- 過大・ノード数不足で把持候補から除いたクラスタも、所属が登録されていれば隣接平面の根拠として残存。
- 複数クラスタで所属添字が重複した場合、対応表では先に登録したクラスタを優先。基本的には重複のない分割を想定。

**大きな床を把持候補から除外することと、床との幾何関係を無視することは別。** 床の所属ノードとGNGエッジがあれば、次の距離判定には利用。

### 3.5 隣接平面からの距離による突出判定

候補クラスタの重心を $\mathbf{c}_i$、隣接クラスタ $j$ の重心と単位法線を $\mathbf{c}_j,\mathbf{n}_j$ とする:

$$
d_{ij}=\left|\mathbf{n}_j^{\mathsf T}(\mathbf{c}_i-\mathbf{c}_j)\right|,
\qquad d_i=\min_{j\in\mathcal{N}_i^{\mathrm{valid}}}d_{ij}.
$$

有効な隣接平面がある場合、$d_i$ が `minimum_protrusion_distance` より小さければ棄却。等しい場合は通過。棄却数は `rejected_low_protrusion_region` に集計。

- 絶対値のため、隣接法線の符号反転に不変。
- 無効な法線、ほぼゼロの法線、無効な隣接重心は距離計算から除外。
- 隣接クラスタがない場合、または全隣接平面が無効な場合は距離条件をスキップ。
- 距離の対象は「候補の重心」と「隣接する無限平面」。候補矩形中心からの距離でも、パッチ境界同士の距離でもない。
- 「突出」という名称だが、上方向への突出量や凸形状の判定ではない。平面の裏側でも同じ距離になり、指先・ハンド基部のクリアランスを保証しない。

### 3.6 TCP位置・姿勢の生成

TCP位置は、水平投影矩形の中心と、候補所属ノードの最高位置から構成:

$$
\mathbf{t}=\mathbf{u}c_{uv,x}+\mathbf{v}c_{uv,y}
            +\mathbf{w}(h_i+s).
$$

$s$ は `tcp_standoff`。正値なら上方へのオフセット。`surface_height` は $h_i$ であり、物体の厚さや全高ではない。矩形中心はクラスタ重心と必ずしも一致しない。

採用した矩形のローカルY軸を $\mathbf{e}_y$ として:

$$
\mathbf{y}=\mathbf{u}e_{y,x}+\mathbf{v}e_{y,y},
\quad \mathbf{z}=-\mathbf{w},
\quad \mathbf{x}=\mathbf{y}\times\mathbf{z},
\quad R=[\mathbf{x}\ \mathbf{y}\ \mathbf{z}].
$$

$R$ を正規化クォータニオンへ変換して出力。$\mathbf{e}_y$ は採用角度の $\mathbf{b}$。TCPのローカルZ軸は常に下向きで、候補面の傾斜へ追従する姿勢ではない。

単独・複合の各候補に対して出力姿勢は1つ。yawの評価は矩形包含用であり、複数yaw候補の出力や矩形内の複数位置・把持深さの探索はなし。

`GraspCandidateArray.header` は `candidate_frame` と入力観測時刻、`tcp_frame` は全候補が目標とする TCP link を示す。ToPoDualArm の既定は `L_tcp`。候補の `Pose` はこの TCP の目標姿勢であり、配列を受け取る側は `header.frame_id` と `tcp_frame` の両方を確認して IK・可視化・軌道評価へ渡す。

上方把持の候補IDは、入力の平面クラスタが持つ永続的な `PlaneCluster.id`。同じIDの生候補が`candidate_confirm_updates`回連続で有効になってから公開し、公開済み候補は`candidate_missing_update_allowance`更新の短期欠測を保持する。位置は指数移動平均、姿勢は把持対称の180 deg yawを同一視したSlerpで平滑化する。TCP位置差が`candidate_track_reset_dist`を超えた候補、入力座標系の変更、TF取得失敗は保持せず再確認または即時消去の対象。

### 3.7 スコアと出力順序

候補に付く数値スコア:

$$
f_i=\frac{L_x L_y}{\max(U_xU_y,10^{-12})}.
$$

`footprint_fill_ratio` は、使用可能な把持面積に対する採用OBB面積の比。観測点による面内充填率、平面そのものの面積比、成功確率ではない。正常な設定・採用候補では概ね0〜1。

並べ替えは次の優先順:

1. `surface_height` の降順。
2. 高さが等しい場合のみ `footprint_fill_ratio` の降順。
3. `maximum_candidates` 件まで保持。

したがって出力先頭が面積比最大とは限らない。現在は固定条件による棄却と並べ替えであり、ファジーメンバーシップや複数根拠のファジー統合は未導入。同じ高さ・面積比の候補間の順序固定も保証なし。ただし同一平面クラスタが継続する間は配列順が変わっても候補IDを維持。

### 3.8 非平面付属部分と上方障害物

平面OBB、TCP、面積比は平面ノードだけから算出し、非平面ノードを混ぜて再フィットしない。

1. GNGエッジと非平面ノード経由の接続から隣接平面を取得し、有効な外形が開口に収まらない平面を参照面として選択。参照面がない場合は付属抽出を省略し、他条件を満たす平面候補は維持。
2. 平面ノードを始点とする幅優先探索で非平面ノードを抽出。参照面の法線を候補重心側へそろえ、符号付き離隔と入口エッジ長で選別。他平面と`BOUNDARY_FREE_SPACE`の端点を経由しない。累積距離と平面OBB外側余白による制限はなし。境界ビットは観測根拠であり、物体端の確定ではない。
3. 付属ノードが固定TCPの開口内に収まらない場合、`rejected_attached_oversize`として棄却。付属ノードの座標と開口寸法との直接比較。付属込みの局所外形は`target_extent_x/y`、平面OBBは従来の`extent_x/y`に分離。
4. 接続や平面所属によらず、全グラフの有限位置ノードを上方の矩形柱で確認。平面最高位置より上で、`approach_height + max(0, tcp_standoff)`までの高さで、開口XY寸法に`approach_margin`を足した領域に観測ノードがあれば`rejected_approach_obstacle`として棄却。

付属抽出は参照平面方式に固定し、方式切替や付属抽出のON/OFF設定はなし。成分IDとノード添字は同一フレーム内だけで使用。`NONPLANE_COMPONENT_NONE`も幾何条件を満たせば付属対象とし、成分数の集計だけから除外。上方障害物の確認は独立した`enable_approach_check`で制御し、参照面がない場合も有効。

**矩形柱は候補絞り込み用の簡易モデルであり、指・手首の実グリッパ体積ではない。** グリッパ体積graphの`required_occupied`等との照合は、この推定器には未接続。点がない場所は自由空間と証明されたわけではなく、ノード間・未観測の衝突、両指支持、把持深さ、摩擦は保証しない。上方許容幅内の突起は許容し、これを超える取っ手はTCPを上げて回避せず、その平面シードを棄却。

### 3.9 処理の要約

```text
グラフとクラスタの更新番号・座標系が一致しなければ処理待ち
各クラスタの入力を確認し、ノード所属表へ登録
上方向との法線傾斜角で候補面を限定
各クラスタの投影凸包から、回転を考慮したサイズ適合性を記録
GNGエッジからクラスタ隣接集合を構築
組合せONなら隣接平面の凸包を合算し、追加のたびに向きと寸法を再評価
単独・複合候補について:
    有効な隣接平面までの重心距離の最小値を取得
    距離根拠があり、突出条件を満たさなければ棄却
    矩形中心・最高位置・下向き姿勢からTCP候補を生成
    上方観測障害物と局所付属ノードの開口包含を判定
候補を高さ優先で並べ、件数上限を適用
候補姿勢、面積比、診断情報を配信
```

## 5. 計算コストと方式の特徴

全GNGノード数を $N$、エッジ数を $E$、クラスタ数を $K$、所属ノード数の総和を $S$、クラスタ隣接組数を $A$、件数制限前の候補数を $M$ とする。

組合せ探索・付属探索・障害物判定を除く、平面シード生成の計算量の見積もり（クラスタ $i$ のノード数を $n_i$）:

$$
O(N+S+E+K+A+\sum_i n_i\log n_i+M\log M).
$$

ハッシュ集合への操作を平均定数時間とした見積もりであり、実測時間ではない。評価対象候補数を$M$として上方障害物の確認に$O(MN)$、付属探索には候補ごとの訪問済み表初期化$O(N)$と到達部分の幅優先探索のコストが追加。探索先ごとに参照面との距離を確認。累積距離制限はなく、探索量はグラフの接続と判定条件に依存。

- 各領域の凸包構築は $O(n_i\log n_i)$。凸包頂点数を $h_i$ とすると、切替角の整列は $O(h_i\log h_i)$、支持点の回転キャリパー走査は $O(h_i)$。角度ごとの全所属ノード再走査や反復最適化は不要。
- 組合せ候補では追加のたびに両凸包の頂点を合算・再整列。全ノードの再投影は不要だが、探索した組合せ数に応じた追加コストあり。
- クラスタ全対比較ではなく、既存GNGエッジを隣接関係として再利用。
- 空間内の位置・姿勢の総当たり探索は不要。
- 平面・OBB・障害物判定は更新ごとの再計算。候補公開層だけは平面クラスタIDで時系列追跡し、短期欠測保持と姿勢・位置平滑化を行う。
- ROS受信・シリアライズ、前段GNG・クラスタ生成、Marker・Viewer描画のコストは上記推定器とは別。

## 6. ROS出力と起動

```bash
ros2 launch grasping_system top_grasp_pose_candidates.launch.py \
  params_file:=/ros2_ws/src/gng_vlut_system/config/ToPoDualArm.yaml
```

出力はGraspCandidateArrayの/grasp_pose_cands、診断は同接頭辞のsummary。
入力は同一frame・更新番号のグラフと平面クラスタ。node_indicesは永続IDではない配列添字。
旧綴りのplanar_clusters_topicは[launch](../launch/top_grasp_pose_candidates.launch.py)を参照。
入力停止時の旧候補の自動失効はないため、stamp・更新番号を併せて確認。

到達性はTCP位置の登録範囲で、姿勢や把持成功の保証ではない。
形状スコアの対応には候補内shape_scoreを使用。候補生成方式の同時配信はトピックを分離。
計画ノードは候補軌道・関節角の出力専用で、ロボット駆動は別接続。

## 7. 検証済み範囲と注意点

### 既存の確認根拠

- 合成テストで壁面の法線棄却、床のサイズ棄却、突出不足、法線符号反転、付属込み包含、距離・深さ・余白制限、別平面への橋渡し、自由空間境界、未接続の上方障害物、入力フレーム不一致を確認。Docker内の実launchでも標準・個別トピックの両方で候補生成・障害物による空配信・除去後の復帰を確認。
- このテストは候補推定器の入力を人工的に組み立てたもの。前段の平面検出精度や実センサの欠損を検証したものではない。
- 2026-08-27の検証記録には、GraspNet scene 3で16〜17領域から候補1〜2件、候補推定部分0.06〜0.07 msの報告あり。
- 過去の設定・環境での記録であり、今回の再測定結果ではない。現在の15 cm把持面設定に対する性能値として転用しない。

### 解釈上の制約

| 条件・現象 | 現方式への影響 |
| --- | --- |
| 遮蔽による領域欠損 | 観測寸法の過小評価と、実物は大きいのに適合する候補の発生 |
| 平面の過分割 | 大きな面の小片がサイズ条件を通過。隣接情報があれば突出判定で一部抑制 |
| 平面の過統合 | 本来の把持部分まで過大領域に含まれ、候補から脱落 |
| GNGエッジの切断 | 隣接平面による棄却根拠が消失。孤立候補として通過する可能性 |
| 側面や細い帯 | 側面は法線傾斜で除外。上向きの細い帯は専用の最小幅条件なし |
| 凹形状や穴 | OBBは空隙も包含。矩形中心が実表面・接触可能位置に載る保証なし |
| 円形・正方形に近い分布 | 同一凸包には同一方向を選択。ただし境界変化による同等方向間のyaw切替はあり、時間平滑化だけで完全には防止不能 |
| サンプリング密度の変化 | 同一凸包を保つ内点・重複点の変化には不変。境界点の欠損や外れ値には依存 |
| 高さ方向の外れ値 | 最大高さを使うためTCP位置に直接影響 |
| 隣接しない障害物 | 簡易上方矩形柱内の観測ノードは棄却根拠。実ハンド基部や未観測部分の衝突は未評価 |

把持候補の生成と、両指接触・適切な開口幅・把持深さ・摩擦安定性・実機成功の評価は区別が必要。到達性や軌道生成も本方式の採用条件には含まれない。
