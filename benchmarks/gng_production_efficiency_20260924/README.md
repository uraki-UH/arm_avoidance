# 本番CPU GNGの結果保持型の効率化

本番CPUの最小空きノードID探索と入力voxelの重心走査を変更した比較。独立実験版では基数ソートを標準ONへ変更。本番版のBoostソート、セル内加算順、全点照合、重点学習、ノード・エッジ更新は保持。

## 条件

- 変更前: `d0f65043757b6bf63ff38c355e2b4b5cd929d232`の`ais_gng_cpu/src/gng_cpu`。保存ソースと同コミットの主要変更対象ファイルの一致を確認。
- Release、GCC 11、既存のLTO有効。認証OFF・フレームログONは元の本番設定と同じ。CPU 0固定、既存コンテナ内。
- `Macnica_交差点分析/algo_0000_ros2/algo_0000_ros2.db3`の`/lidar_points`、フレームごとに異なる連続入力。元入力は約16万点、入力上限20万点、ノード上限2万、学習4,000回、`node.grid=0.5`。設定は[保存済みYAML](../gng_runtime_trials_20260924/at128_voxel_0_1.yaml)を使用し、入力voxel幅だけ切替。
- 初回300フレーム、先頭50フレームを計時集計から除外。別2試行は100フレーム。再現性比較は全3試行共通の50〜99フレーム。2試行目はafter→beforeの順序。
- 比較専用コピーのみ乱数シードとLPFの時間刻み0.1秒を固定し、段階時間・中間点群参照を追加。本番の乱数・実時間は変更なし。
- 時間は点群転送＋CPU GNG＋グラフ出力。bag読込・逆シリアル化・ハッシュは計時外。ROS配送、ROS側平面・曲面フィッティング、分類器、Viewer描画は対象外。

## 連続300フレームの平均

| 入力voxel幅 | 変更前 | 変更後 | 短縮率 |
| --- | ---: | ---: | ---: |
| 0.1 m | 110.877 ms | 107.034 ms | 3.5% |
| 0.5 m | 52.159 ms | 39.348 ms | 24.6% |

初回フレームは0.1 mで324.509→147.089 ms、0.5 mで211.773→99.303 ms。初回はノード追加が集中する条件であり、定常時と別集計。

## 同一区間の3試行中央値

| 入力voxel幅 | 変更前 | 変更後 | 短縮率 |
| --- | ---: | ---: | ---: |
| 0.1 m | 111.962 ms | 107.861 ms | 3.7% |
| 0.5 m | 51.171 ms | 39.539 ms | 22.7% |

全6組で変更後の実行時間が短縮。ボクセル間引きなしの100フレームでは169.859→164.338 ms。生点群では重心走査統合は通らず、空きID管理の変更だけの比較。

0.1 mの変更後は全点照合・重点候補生成74.803 ms、voxel整理10.530 ms、学習5.416 ms。0.5 mではそれぞれ12.105、8.093、4.537 ms。全点照合が残るため、最小構成の実験版と同程度の時間にはならない。

## 出力一致

変更前後1,190組、計2,380フレームで、ノード座標・法線・ラベル・ID・生成フレーム・エッジ、クラスタ属性・所属、入力ラベル、入力voxel重心・元点添字・区間・点数・重点候補数が一致。全フレームで学習4,000回。

うち90組は重み付き重点入力、観測レイ、共分散・支持統計、勝者rank 1/2の学習イベント、ノード・エッジ差分を有効化し、それらの出力も一致。観測角度表・compact経路は既存の観測APIテストで検証。APIのHuman／Car分類テストも成功。

変更前CTest 13件＋API 2件、変更後14件＋API 2件、実験版21件、通常本番14件＋API 2件、計68件成功。追加の空きID回帰テストは2万回の追加・削除と、セル上限・容量上限・範囲外・再初期化を含む最小ID照合。

本番は通常ビルドからインストール先の共有ライブラリを原子的に更新。公開API・YAML・launch変更なし。インストール済みの非固定乱数・実時間版で実点群30フレームと重点入力・観測・差分取得を確認。比較専用シンボルが本番バイナリにないことも確認。

## 再現

既存`gng_cpu_container`内で以下を実行。`before_source`は`artifacts/gng_production_efficiency_20260924/`へ保存済み。新規checkoutでは上記基準コミットの対象パッケージを同じ場所へ展開する必要あり。ビルドスクリプトは比較コピーの上書きを禁止。

```bash
bash /ros2_ws/src/benchmarks/gng_production_efficiency_20260924/build.sh
bash /ros2_ws/src/benchmarks/gng_production_efficiency_20260924/run.sh
python3 /ros2_ws/src/benchmarks/gng_production_efficiency_20260924/summarize.py
```

初回の0.1 m・30フレーム・拡張機能検証は、`benchmark.py --frames 30 --warmup 5 --voxel 0.1 --features`でbefore／afterを実行し、各`smoke.json`へ保存。再現用の`run.sh`には、この初回条件も含めて全条件を収録。

通常ビルド・本番反映・インストール先の実入力テストで使用したコマンド:

```bash
bash /ros2_ws/src/benchmarks/gng_production_efficiency_20260924/install_validated.sh
```

反映スクリプトは今回の基準SHA-256を検査する、一回の適用用。既に更新済みの環境では再反映を拒否。

## 保存物と限界

[集計](summary.json)、[ソース基準](base_revision.txt)、[本番反映](install.json)、[後片付け](verification.json)、[ライブラリSHA-256](library_sha256.json)を保存。生ログ・フレームJSON・共有ライブラリ・変更前後ソースはGit対象外の`artifacts/gng_production_efficiency_20260924/`。

同じ入力・乱数列・時間刻みに対する一致を示す単一bagの検証。他データ・異なるコンパイラ・任意の実行タイミングでの完全一致を一般保証するものではない。作業中に外部で既存GNGの3プロセスが終了し、負荷条件は変化し得る。CPU固定、順序を入れ替えた3試行でも改善を確認。エージェントによる既存ROS・Viewer・bagの停止／再起動操作なし。

検証の全プロセスは終了し、一時ビルドと生成キャッシュは削除済み。最終確認ではViewer関連8プロセスとbag再生が継続、GNG本体は未起動。次回の通常launchで更新済みライブラリを使用。
