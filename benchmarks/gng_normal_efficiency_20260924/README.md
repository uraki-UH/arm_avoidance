# CPU GNGの法線・曲率計算の効率化

既に基数ソートを採用した本番CPU版から、法線・曲率のメモリ参照と差分ベクトル計算を変更。同じ入力・乱数・時間刻みで出力を照合し、採用した実装を本番へ反映。

## 実装

- `Labelling`で座標と法線をそれぞれ連続配列に保持。初期化時に確保し、毎フレームの有効ノード値を集約。大きな`Node`構造体への隣接参照を削減。
- 法線計算では中心位置と隣接点との差分を再利用。外積の組、正規化、符号判定、加算順は維持。
- 全ノードの法線を確定後、曲率を計算する従来の2段階構成を維持。全有効ノードを毎フレーム更新し、ラベルのLPFも継続。
- 2万ノードで追加バッファ約480 KB。ノード削除・ID再利用・再初期化にも対応。
- 入力、学習4,000回、全点照合、重点配分、接続・寿命、クラスタ、観測・統計機能は維持。近似法線、更新間引き、並列化、fast-mathの追加なし。

## 比較条件

同じ交差点bagの`/lidar_points`、入力約16万点、上限20万点、ノード上限2万、`node.grid=0.5`。[設定](../gng_runtime_trials_20260924/at128_voxel_0_1.yaml)の入力voxel幅だけ0.1／0.5／0へ変更。

既存GNG・Viewer・bag再生を継続。Release＋既存LTO、CPU 0固定、認証OFF・フレームログON。比較コピーだけ乱数と時間刻み0.1秒を固定。最初の試行は連続300フレーム、追加2試行は100フレーム。集計から最初の50フレームを除外し、第2試行は実行順を反転。点群転送＋GNG＋出力取得を計時し、読込・ハッシュ処理は計時外。

`normal_ms`は連続配列への集約と法線生成、`rho_label_ms`は曲率・ラベル・LPF・必要な差分記録。ノードごとのタイマー追加なし。

## 300フレーム比較

| voxel幅 | 処理 | 変更前 → 変更後 | 短縮率 |
| --- | --- | ---: | ---: |
| 0.1 m | 法線 | 3.564 → 3.120 ms | 12.5% |
| 0.1 m | 曲率・ラベル | 2.024 → 1.576 ms | 22.1% |
| 0.1 m | 法線・曲率・ラベル全体 | 5.588 → 4.697 ms | 16.0% |
| 0.5 m | 法線 | 2.226 → 2.042 ms | 8.3% |
| 0.5 m | 曲率・ラベル | 1.762 → 1.454 ms | 17.4% |
| 0.5 m | 法線・曲率・ラベル全体 | 3.988 → 3.497 ms | 12.3% |

3試行共通区間（50〜99フレーム）の中央値でも、法線周りは5.523→4.637 ms／3.986→3.450 msへ短縮。連続配列だけの候補から、差分再利用を加えた候補でさらに約0.08 ms短縮した短時間比較も保存。

GNG全体は300フレームで109.083→106.476 ms／37.592→37.815 ms。3試行共通区間の中央値では109.719→109.110 ms／37.573→37.512 ms。特に0.5 mの全体改善は小さく、試行によって増減。法線周りの12〜16%短縮をGNG全体の短縮率とは扱わない。

0.1 mの変更後も全点照合・重点候補生成が約80.2 ms。学習・クラスタ等の変動もあるため、全体の短縮を法線変更だけに帰属させない。

## 結果一致と検証

- 短時間3構成・各幅80フレーム、連続／反復試行、voxel無効を含む拡張機能の30フレーム比較を実施。計2,660フレームを実行し、保存済み基準の再利用を含む1,410組で全比較項目が一致。
- 法線、曲率、座標、ノード・エッジ、クラスタ、入力ラベル、voxel対応、重点候補数が一致。全フレーム4,000回学習。
- 拡張機能90組では観測範囲、共分散・支持統計、重み付き重点入力、学習イベント、ノード・エッジ差分も一致。
- 比較3構成のテスト各17件、追加回帰テスト1件、本番18件、計70件成功。回帰テストは位置変更・隣接順変更・欠番・ID再利用・サイズの異なる再初期化・同一形状でのLPF継続を確認。
- インストール済みの実時間・非固定乱数版でも実点群30フレームと拡張機能の動作を確認。
- 回帰テストの初回登録はコンテナ所有ファイルへの書込失敗で0件となり、検証成功とは扱わず登録を修正。再ビルド時のROS環境未読込による失敗も修正し、`--no-tests=error`付きで1件の成功を確認。各試行の失敗ログも保存。

## 再現

`gng_cpu_container`内、保存先が未作成の状態:

```bash
python3 /ros2_ws/src/benchmarks/gng_normal_efficiency_20260924/prepare_sources.py
bash /ros2_ws/src/benchmarks/gng_normal_efficiency_20260924/build.sh
bash /ros2_ws/src/benchmarks/gng_normal_efficiency_20260924/build_reuse.sh
bash /ros2_ws/src/benchmarks/gng_normal_efficiency_20260924/probe.sh
bash /ros2_ws/src/benchmarks/gng_normal_efficiency_20260924/probe_reuse.sh
bash /ros2_ws/src/benchmarks/gng_normal_efficiency_20260924/run.sh
python3 /ros2_ws/src/benchmarks/gng_normal_efficiency_20260924/summarize.py
```

基準は[コミット](base_revision.txt)。`prepare_sources.py`はそのコミットから本番パッケージを展開し、既存の保存コピーを上書きしない。`after`は連続配列だけ、`reuse`が最終採用版。`optimize.py`は指定したソースコピーへの変更用。

既存GNGは旧ライブラリを保持したまま稼働。更新版は次回の通常起動から有効。

本番反映には`bash /ros2_ws/src/benchmarks/gng_normal_efficiency_20260924/install_validated.sh`を使用。検証済み集計と変更前ライブラリのSHA-256を確認する、今回の反映専用スクリプト。反映済み環境での再適用不可。

比較ソース・ライブラリ・生JSON・ログは`artifacts/gng_normal_efficiency_20260924/`、一時ビルドは`/tmp/gng_normal_efficiency_build/`。通常のcolcon探索から除外。

[集計](summary.json)と[リリース記録](../../gng_vlut_system/docs/releases/2026-09-24_gng_normal_efficiency.md)を参照。単一bag・同じ乱数列／時間刻みでの一致検証であり、任意環境・別コンパイラでの速度や完全一致の保証ではない。
