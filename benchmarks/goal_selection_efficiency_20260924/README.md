# 目標選択の全体走査削減とbsp3d差分更新（2026-09-24）

採用実装は、特徴量・出力ノード参照表の再利用と、bsp3dの移動・追加・削除APIによる差分更新。旧SpatialTreeへの復帰なし。空間索引の方式だけを変更した初回比較と、今回の全体処理削減を区別。

## 実装

- 特徴量受信時に16bit IDから特徴量への直接参照表を更新。選択のたびに全特徴量のhash表を再構築する処理を削減。同一IDの最後の特徴量を優先。
- map受信時にIDから全該当ノード添字への参照表を更新。選択IDから直接出力ノードを収集し、元配列の順序へ整列。重複IDの別位置・衝突ラベル・非有限位置のノードも、選択IDに一致すれば従来どおり出力。
- 空間索引は配列添字に対応する要素を`deque`へ保持。移動は`updatePosition`、有限点の追加・削除・無効化は`add`・`remove`。件数変更時も残存要素のアドレスと索引ハンドルが有効。
- 座標が変わったという理由だけでツリー全体を破棄する処理を廃止。bsp3d内部で必要な分割・部分木再構成は継続。
- TF・ラベル・ID・法線・headerのみの変化では空間索引を再利用。参照表と入力メッセージが一致しなければ旧処理へフォールバック。不変の受信スナップショットを前提。
- 参照表の配列は18,729ノード・64bitで約1.14 MiB。索引・受信メッセージ・出力のメモリは別。

今回の変更対象は目標選択。CPU GNGの学習規則・YAML・学習ライブラリ・スレッド構成の変更なし。

## 比較方法

- 同一バイナリ・同一プロセスで7方式を各反復ごとに無作為な順序で実行。旧SpatialTreeは比較専用名前空間へ分離し、ODR違反を回避。
- GCC 11.4、C++17、`-O3 -DNDEBUG`、CPU 0固定。3試行。既存ROS・GNGと同居し、周波数・外部負荷の固定なし。
- 各条件70反復、先頭10を除く60反復の平均を計算し、その3試行中央値を表に記載。間欠更新の費用が中央値から消えないよう、合計時間には試行内平均を使用。
- 時間はmap索引・ID表更新、特徴量参照表更新、選択・結果構築の合計。入力メッセージの生成・破棄、ROSの転送・publish、viewerは対象外。
- 古い共有メッセージは各反復の測定終了まで保持。最後に実行した方式だけへ破棄時間を計上しない条件。初回のその保持なしの比較は`first_comparison/`、差分索引導入前の比較は`cache_only_comparison/`に別保存。
- 比較元は`base_revision.txt`のコミットと`before.patch`で再現。`old_before`は移行前の8分木＋元選択、`bsp_before`は移行直後のbsp3d＋元選択、`old_cached`・`bsp_cached`は参照表だけの追加、`bsp_features`・`bsp_output`は各参照表だけの追加、`bsp_incremental`が採用版。
- 旧8分木を同じ差分更新へ改修した比較ではない。下表は実装前後の比較であり、木の方式の一般的な優劣を示すものではない。

## 入力と更新条件

- `robot`: 既定設定`ToPoDualArm.yaml`が参照する`gng_results/ToPoDualArm10000/gng.bin`の有効座標10,801点、座標layer 0。version 9の読取専用抽出。
- `points`: 保存済みCPU GNGの18,729座標。出典は`fixtures.json`。
- `planar`: 薄い合成平面20,000点、原点重複500点。保存座標の指紋は`fixtures.json`。
- IDは連番、ラベル・法線・可操作性・候補・TFは全方式共通の合成条件。実座標を使った比較であり、実環境のROS処理全体を再生した測定ではない。
- `moving`: 保存座標のXを1〜7 mmずらし、全点変更を毎回反映。`sparse`はその対象が5%。`occasional`は20選択に1回の全点変更。いずれも再構築・差分更新を比べる人工条件。
- `publish_30hz`: 同じ座標のmapと特徴量を6回受信して1回選択するCPU処理量。配信30Hz・選択5Hzを想定した条件で、実際の周期でROSメッセージを流した時間測定ではない。
- 目標選択の既定入力は保存GNG由来の`/ToPoDualArm/Tmap_static`。TF変化だけでは索引内の座標は変わらない。学習中GNGのノード位置更新と静的マップの再配信は区別。
