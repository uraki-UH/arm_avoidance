# 本番CPU相当の基数ソート検証

この文書は単一シード比較時点の記録。後続の[複数シード検証](../gng_radix_multiseed_20260924/README.md)で完全一致を採用条件とする判断を見直し、本番CPUへ入力ソートを採用。以下の当時の結果・判断は履歴として保持。

前回の結果保持型の効率化を適用した本番ソースから、[独立コピー](../../ais_gng_cpu/experimental/gng_radix_trials/README.md)を作成。Boostの整数ソートと、全32bitセル番号による安定な4パス基数ソートを比較。全点照合・重点学習・観測・ノード／エッジ更新・クラスタ処理を維持。

## 比較条件

- 元コミットは[基準リビジョン](base_revision.txt)。本番53ファイルとインストール済みライブラリのSHA-256不変を確認。
- Release、GCC 11、LTO有効、CPU 0固定。認証OFF・フレームログON。各方式3試行、2試行目はradix→Boostの順で実行。
- 同じ交差点bagの`/lidar_points`をSQLiteから連続取得。入力約16万点、上限20万点、ノード上限2万、学習4,000回、`node.grid=0.5`。[設定](../gng_runtime_trials_20260924/at128_voxel_0_1.yaml)の`input.voxel_grid_unit`だけ0.1・0.5・0へ変更。
- 初回は300フレーム、追加2試行は100フレーム。平均時間は先頭50フレーム除外。反復比較は全試行共通の50〜99フレーム。
- 比較コピーのみ同じ乱数シード・LPF時間刻み0.1秒を固定。ソート時間と段階時間、初回の学習入力を記録。重点入力等の検証では全30フレームの学習点を記録。
- 時間は点群転送＋CPU GNG＋グラフ出力。bag読込・逆シリアル化・ハッシュ・被覆評価・スナップショット保存は計時外。学習点の記録は通常計測の初回だけで、時間平均から除外。

## 連続300フレームの平均

| voxel幅 | 全体 Boost → radix | 短縮 | ソート単体 Boost → radix | 短縮 |
| --- | ---: | ---: | ---: | ---: |
| 0.1 m | 108.996 → 99.970 ms | 8.3% | 9.043 → 2.291 ms | 74.7% |
| 0.5 m | 39.746 → 35.396 ms | 10.9% | 6.918 → 2.887 ms | 58.3% |

3試行共通区間の中央値でも、0.1 mは110.486→102.151 ms、0.5 mは40.028→35.294 ms。6組すべてで全体時間を短縮。

全体時間にはグラフの変化による後段の処理量差も含む。ソート単体は同じ全点・同じセル番号を処理した比較。全点照合等が残るため、ソート単体の58〜75%短縮が、そのままGNG全体の短縮率にはならない。

## 入力と出力の一致

全1,090組・計2,180フレームで、保持点数・セル個数・全元点のセル対応・整列後のセル番号列・各セルの区間が一致。学習回数は全フレーム4,000回。元点の欠落・重複と、セル番号の低ビット省略はなし。

比較用Boost版は、前回の本番相当版と0.1・0.5 mの各300フレーム、計600フレームでグラフ・クラスタ・入力ラベル・voxel出力が完全一致。

一方、voxel有効時の基数ソート版は、両幅で座標を含むグラフと、ID・生成フレーム・ラベル・接続だけのグラフ構造のどちらも300フレーム中0件一致。初回から差が発生。重点入力・観測・統計・イベント・差分の出力も変化。

voxel無効の対照条件30フレームでは、グラフ・クラスタ・入力対応・学習点・イベント・差分・統計・観測の全項目が完全一致。

## 丸め差以外の変化

最初のフレームの比較:

| voxel幅 | 重心の最大成分差 | 異なる学習点 | 1 mmを超える学習点差 | 学習点の最大距離差 |
| --- | ---: | ---: | ---: | ---: |
| 0.1 m | 0.00381 mm | 1,479 / 4,000 | 1,430 / 4,000 | 0.122489 m |
| 0.5 m | 0.01526 mm | 2,859 / 4,000 | 2,504 / 4,000 | 0.681134 m |

初回の重点候補数は0.1 mで85,770点、0.5 mで5,325点で、候補ラベルも両方式で一致。それでもセル内の元点順序が変わり、同じ乱数添字から別の元点を選択。候補配列を持たない最小構成での「重心の丸め差だけ」という説明は、本番の重点サンプリングには適用できない。

観測機能もセル先頭の元点を代表点として参照するため、加算順以外の影響経路が存在。学習点の選び方と確率配分のコードは保持しているが、同一乱数列に対する実際の選択点は変化。

## 点群の被覆

0.2 m／0.4 m以内にノードがある入力点の割合。YAML範囲内の有限な非原点点を評価し、学習入力からの原点除外はなし。300フレーム中、ウォームアップ後の26フレームを等間隔と最終フレームで評価。

| voxel幅 | 0.2 m被覆率 Boost → radix | 0.4 m被覆率 Boost → radix | 最近傍ノード距離の平均 |
| --- | ---: | ---: | ---: |
| 0.1 m | 75.577% → 75.938% | 95.468% → 95.496% | 0.175583 → 0.174650 m |
| 0.5 m | 59.659% → 59.725% | 98.227% → 98.356% | 0.183759 → 0.183447 m |

平均0.2 m被覆率は、このbagでは0.1 mで+0.361ポイント、0.5 mで+0.066ポイント。フレームごとの差はそれぞれ−0.125〜+0.733ポイント、−0.916〜+1.201ポイントで、全フレームの改善を示すものではない。

## 判断・検証範囲

「学習結果に影響しない効率化なら本番を変更可」という条件に対し、完全一致を満たさないため今回の本番採用は見送り。独立比較版として保存。既存の最小実験版の基数ソート標準ON設定は継続。

Boost／radixのそれぞれでCTest 15件と既存APIテスト2件、合計34件成功。追加テストは全32bitの大小関係、同値キーの安定性、全点保存、末尾保護を`std::stable_sort`と照合。空・1点・257点・8,192点・200,000点を含む。

通常`colcon list`は30パッケージ、`gng_cpu`は1件で、検証コピーの混入なし。既存ROS関連9プロセスは前後不変。ビルド・測定・集計の全プロセス終了、一時ビルド削除済み。本番へのインストールなし。

単一bag・同一乱数列の評価であり、認識精度・全環境での被覆の同等性や改善を保証する結果ではない。ROS配送、平面／曲面フィッティング、分類器、Viewer描画は未計測。

## 再現と保存先

既存`gng_cpu_container`内:

```bash
bash /ros2_ws/src/benchmarks/gng_radix_production_20260924/build.sh
bash /ros2_ws/src/benchmarks/gng_radix_production_20260924/run.sh
python3 /ros2_ws/src/benchmarks/gng_radix_production_20260924/summarize.py
```

すべて有限タイムアウト付きで実行。ビルド・測定の保存先は`artifacts/gng_radix_production_20260924/`。本番インストール先は使用しない。
