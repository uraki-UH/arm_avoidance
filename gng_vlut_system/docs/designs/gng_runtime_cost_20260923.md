# CPU GNGの実行時間ボトルネック調査（2026-09-23）

## 結論
()
主なボトルネックは学習更新ではなく、学習前に全入力ボクセルを既存ノードへ照合する処理。
計測条件ではGNG全体103〜107 ms/frameのうち、この前処理が74〜76 ms/frame（約7割）。
関数別の標本計測でも`CUGNG::getDownSamplingGrid()`が主要因。

- 学習4,000回に対し、学習前の近傍照合は約78,000回/frame。
- 学習回数を1/4にしても全体は約103 ms。学習回数だけの調整では主要コストが残存。
- 改善の第一候補は全ボクセル近傍照合の局所性・重複処理。ノード寿命・生成・接続・学習配分の維持が条件。

本書は通常CPU版`ais_gng_cpu/src/gng_cpu`の当時計測の整理。GPU版、ロボット姿勢用GNG、L0、
`experimental/gng_spatial_tree`の性能評価は対象外。その後のコード・YAML変更後の性能を保証する数値ではない。

2026-09-24追記：削減候補の`voxel2node_ids`生成・整列は削除済み。[同値性・効果の確認](../releases/2026-09-24_gng_unused_mapping.md)。以下の数値・候補表は調査当時の記録。

## 条件

計測時の`ais_gng_cpu`の`at128.yaml`相当、約16万点、ノード上限20,000、学習4,000回、探索grid 0.5 m。
平面・曲面は無効。`/scan/transformed`の同一30フレームを独立プロセスで70回再生し、最初の20回を除外。
以下の時間は残る50回の平均。通常・前／後は比較実験を挟んだ基準条件の測定であり、修正前／修正後ではない。
取得XYZとAPI内部のXYZの一致を確認。通常測定はインストール済みReleaseライブラリの一時コピー。
ROS変換・配信・Torch分類は測定対象外。実bag全体の連続再生時間ではない。

## 「全ボクセル照合などの前処理」の内容

処理順は、入力のボクセル化 → `attention()`による全ボクセル照合・グラフ更新 → 選択点の学習 → ラベル・接続維持・内部クラスタリング。
前処理の`attention()`は単なる点群の間引きではなく、以下の役割の組合せ。

| 役割 | 実際の処理 | 省略した場合の影響 |
| --- | --- | --- |
| 近傍照合 | 各ボクセルの代表点について周辺ノードを調べ、最近傍・第二近傍と被覆状態を判定 | 以降の生成・接続・ラベル判定の根拠欠落 |
| 観測による寿命リセット | `node.s1_reset_range`内のノードの`age_s1`を0へ更新 | 観測されていても学習で選ばれないノードの早期削除 |
| ノード生成 | 既存ノードの警戒領域で覆えていない代表点にノードを追加 | 新しく見えた場所や未被覆領域の生成遅延・欠落 |
| 接続更新 | 見つかった最近傍・第二近傍を接続し、既存接続なら接続の年齢を更新 | グラフ接続やエッジ寿命の変化 |
| 重点学習点の抽出 | 未知物体・人物付近の元点を学習候補へ集約 | 通常点と重点点の学習配分の変化 |
| 対応配列の作成・ソート | ボクセル→ノード対応`voxel2node_ids`の作成と並べ替え | 通常CPU版では後続の参照が見当たらず、削減候補。個別効果は未測定 |

この全件処理の後に、`node.learning_num`回の学習で再び近傍探索を実行。
ただし途中でノードの追加・移動があるため、単純に以前の探索結果を再利用できるとは限らない。
この`attention()`は把持候補用の重点学習機能だけを指す名称ではなく、同機能を無効にしても残るコア処理。

- [cugng.cpp](../../../ais_gng_cpu/src/gng_cpu/src/cpu/cugng.cpp): `getDownSampling()`、`getDownSamplingGrid()`、`learn()`、`connect()`、`check_age()`。

## 実測

| 処理 | 通常・前 ms | 通常・後 ms |
|---|---:|---:|
| GNG全体 | 106.75 | 103.05 |
| ボクセル化 V | 9.18 | 9.12 |
| 全ボクセル照合・追加・attention作成 A | 76.38 | 73.78 |
| 学習 L | 5.28 | 4.98 |
| 法線・曲率・ラベル La | 4.68 | 4.24 |
| エッジ・ノード維持 Ch | 2.24 | 2.04 |
| 内部クラスタリング Cl | 5.50 | 5.26 |

内部区間は整数msへ切り捨てた後の平均なので合計は全体と一致しない。API入力コピーは別枠で0.78〜0.90 ms。
最終ノード数は19,944／19,931。別の取得区間でも全体105.71 ms・前処理75.70 msを確認。

`A`はここでは時間区間の記号。通常ログの`I: ..., V: ..., A: ...`にある`A`は重点点数であり、時間ではない。
`Cl`はGNGコア内の既存クラスタリングであり、無効化したCPU直結の平面・曲面検出とは別処理。

### パラメータ変更による比較

同一入力で学習1,000回は全体103.18 ms（前処理76.64、学習1.04）。
ノード上限10,000は全体72.81 ms（前処理51.82、最終9,963ノード）。
前者の全体差は通常計測の変動幅と同程度。後者は約30%短縮だが表現量・クラスタ数も変化。

## 主因の根拠と計算量

`GNG::attention()`→`CUGNG::getDownSampling()`→`getDownSamplingGrid()`が主因。
学習用4,000点とは別に、ボクセル化後の全入力約78,000点を毎フレーム照合。
各入力で最大27セル×各10ノードを訪問。全ノード総当たりではなく、各探索の候補数には上限あり。
主な処理量は全入力ボクセル数と、訪問セル内の候補ノード数に依存。
近い入力点どうしでも同じ周辺セルを繰り返し訪問し、ノード情報への参照と寿命・接続更新が発生。
分散したメモリアクセスやキャッシュ効率は改善仮説であり、キャッシュミス率そのものは未測定。

別の一時ソース・ビルドで16回に1回の時間標本を取得。50フレームで照合3,911,310回、
学習近傍探索200,000回。約19.6倍の呼出回数。照合の標本推定は約74.5 ms/frameで主要関数中最大。
追加ノードの空き探索を含む`add_node`は推定約1.46 ms/frameで、今回の定常区間の主因ではない。
時間標本は偏り・タイマー負荷を含むため排他的な精密内訳や合計には使わない。
入力順の分散処理には、ノード上限を低いZ側だけで使い切らない目的がある。
順序変更による速度低下の単独比較は未実施なので、「シャッフルが主因」とは断定しない。

## 別の問題: ノード上限の二乗メモリ

`edge_count`のuint8配列と`edge_distance`のfloat配列は上限ノード数の二乗で確保。
20,000では2配列で2,000,000,000 byte（約1.86 GiB）、10,000では約0.47 GiB。
これはメモリ上の問題であり、毎フレーム二乗の全走査が主因という意味ではない。

ノード本体・探索グリッド・入力点群などは上記に含まれず、実プロセスの使用量とは別。
`edge.num_max`では、この二つの二乗配列の容量は制限されない。
疎な接続構造への置換はメモリ削減候補だが、探索時間まで短縮するかは比較が必要。

## 改善候補と必要な検証

以下は本調査に基づく候補。通常CPU版への採用・速度改善の確認済み事項ではない。

| 優先度 | 候補 | 確認すべき点 |
| --- | --- | --- |
| 1 | 同一・近接セルの候補参照の共有、探索用位置データの局所性改善 | 最大2近傍の選択、警戒領域判定、セル容量、ノード追加・移動後の索引整合性 |
| 2 | 同一接続・同一ノードへの重複更新の削減 | エッジ寿命、削除・再生成されたID、観測時の寿命リセット、イベント・差分出力の維持 |
| 3 | 使用されていない対応配列・ソートの削減 | 全利用箇所の再確認と、削減した区間の単独計測 |
| 別軸 | 二乗エッジ配列の疎構造化 | メモリ使用量と参照時間の両方、接続上限・寿命判定の維持 |

全件処理の一律省略、単純な間引き、ノード上限削減は出力品質も変更するため、等価な実装最適化とは区別。
SpatialTreeなど別の探索構造も、範囲探索・追加・移動・削除・結果反映まで含めた比較が必要。
最近傍探索だけの速度や、別条件の実験値を本書の103〜107 msと直接比較しない。

再計測では同じ入力・初期状態・設定・乱数条件を揃え、基準版を実験の前後に実行。
時間の平均・分位点・最大値とメモリ量に加え、空間被覆、ノード・エッジ数、連結性、
未観測後の消失と再観測時の復帰を確認。学習を止めた比較と通常学習ありの比較を分離することが望ましい。

## 失敗・制約と実行記録

- 既存GNGの停止・再起動により直接計測条件が変化。調査側からの操作なし。
- param dumpは親boolと子設定の衝突で失敗。停止中のパラメータサービス取得も失敗。
- `map←hesai_lidar`のTF欠落は直前の既存GNGログでも確認。直接入力のその試行は採用せず、最終比較は変換済み出力を使用。座標の正しさは対象外。
- 初回取得の定常約110ノード・211ボクセルの区間は、目的の約2万ノード条件と違うため主結果から除外。
- ホストperfの制限やsudo認証設定は変更せず。一時コピーの内部計測を使用。
- 本調査後に入力ボクセルサイズ0の扱い・動的パラメータ反映・長期記憶寿命の設定化などの変更あり。現在の設定への数値の流用は不可。
- 計測時の完全な設定ダンプ、ソース差分・ライブラリのハッシュ、CPU・コンパイラ条件は本記録に未保存。厳密な同一条件の再現保証なし。
