# 静止した巨大平面のGNGノード配分

## 1. 要約

2026-09-24、ユーザー指定に基づく設計案。対象は、繰り返し観測される大きな平面の内部。実装・設定変更・性能検証は未実施。

**面の位置と広がりを維持する粗い支持ノードを残し、過密な内部への追加・学習を抑え、既存の余剰ノードを段階的に整理する。** 平面を別形式の地図として永続保持する実装がないため、ノードを完全にゼロにする方式は初期対象外。

木などの非平面unknownの削減、人・車への積極的な重点配分は別段階。今回の解放枠は通常GNGで利用可能とするが、人・車への再配分を保証するものではない。BBoxによるクラスタ生成、原点群の削除、入力範囲外の独自フィルタは追加対象外。

| 判定対象 | 初期方針 |
| --- | --- |
| 静止 | 固定座標系で同じ支持領域の平面法線・平面位置と現在入力の整合が一定期間継続。既存`static_node`は長期残存フラグのため判定根拠に不使用 |
| 大きさ | 平面内の二方向の広がりと、支持のある連結した粗セル数の併用。`area`、ノード数、extentの積だけによる判定は不可 |
| 内部 | 所属ノード・支持エッジを起点に、現在の元点で平面上の支持を確認できる連続領域を、保護幅だけ内側へ縮めた領域。外周・穴・段差・別平面との接続部は保護 |
| 保護対象 | 人・車と判定されたノードおよび接続近傍、注目対象、境界候補、平面に適合しない現在入力。判断不能な領域は通常密度 |
| 粗さ | 平面内の目標間隔と粗セル別のノード予算。平面に垂直な誤差許容は別設定とし、粗さに合わせて拡大しない |

ここで確認するのは「観測された平面形状の時間的安定性」。同じ平面内の移動や未分類の停車車両まで、平面式だけで静止背景と確定することは不可能。既知対象の保護と、未確定領域を通常密度に残す保守的な判定を採用候補とする。

**状態と適用順序**

```mermaid
flowchart LR
    A[前フレームの平面・保護領域] --> B[現在の元点群で局所的に再確認]
    B --> C[通常／確認中／粗密制御中のセル]
    C --> D[全入力照合・追加判定・学習配分]
    D --> E[連結性を保つ余剰ノード整理]
    E --> F[平面抽出・次フレーム用の状態更新]
    F --> A
```

1. 初期状態は通常。平面候補が大きさ・内部・品質の条件を満たすと確認中へ移行。同じ場所で有効な観測が続いた後に粗密制御を開始。
2. 粗密制御中も現在入力の平面からの距離を元点で確認。物体出現や不整合のあるセルと保護幅内の隣接セルは、そのフレームから通常へ復帰。平面内外が混在する入力voxelは制御対象外。重心だけで平面と判定しない。
3. 再び平面だけが観測されても、確認期間を経てから再適用。粗くする方向は確認付き、細かくする方向は即時。入力欠落時は安定期間を加算せず、追加削減を停止。状態の有効期限切れでは通常へ復帰。
4. 座標系変更、TF不成立、地図初期化、bagループ等の入力時刻逆行で履歴を破棄。クラスタIDの存続だけを安定根拠にしない。分割・統合後は支持領域と平面の整合を再確認。

**サンプリング・追加・削減の共通制御**

| 処理 | 接続方針 |
| --- | --- |
| 学習配分 | 安定平面の内部は粗セル単位で抽選し、各セルの元点数による重複優遇を抑制。観測維持用の学習枠と全体探索枠を確保。平面内部はunknown重点候補からも二重に選択しない |
| 追加抑制 | `getDownSampling()`と`learn_normal()`の両方の追加経路へ同じ判定を適用。対象入力点と既存ノードが同じ有効な平面内部にあり、局所被覆が足りる場合だけ抑制 |
| 既存ノード整理 | 現在も平面として観測される内部だけで、残す代表ノードを既存ノードから選択。観測寿命の短縮で代用せず、フレーム当たりの削減数に上限 |
| 連結性 | まず既存エッジを通じた局所的な縮約を検討。削除ノードの接続を代表へ移す場合も同じ平面の支持領域内に限定。穴を横断する接続、他物体への接続、次数上限超過、成分分断のおそれがあれば削減を見送り |
| 保持条件 | セルの被覆、平面を推定できる非共線な支持点、クラスタ成立に必要な支持数、他領域への接続点を保持。予算は保護・連結性を優先する目標上限。保護により超過した数を記録 |
| 変更の反映 | `delete_node()`・`connect()`・`disconnect()`等の既存経路を使用し、索引・差分出力・空きID・エッジを整合。削除ノードの観測回数や共分散を代表へ単純加算しない |

ノード単位の警戒半径を一律に広げる方法は使用しない。路面から浮いた人・車の点まで「近くにノードあり」と判断するため。粗い目標間隔は有効な平面内の追加抑制にだけ適用し、通常の近傍探索・平面垂直方向の分離条件は維持。

既存の近傍探索の到達範囲・エッジ生成距離・孤立ノード削除・クラスタ接続条件と矛盾する間隔は採用不可。代表間を接続できない場合は支持ノードを余分に残す。全体のエッジ条件を緩めて接続を作る方法は初期対象外。

## 2. 条件・検証

**現在の実装から得られる情報と追加する状態**

- [PlaneCluster](../../../ais_gng_cpu/src/ais_gng_msgs/msg/PlaneCluster.msg)は法線・重心・接線・面幅・局所間隔・平面残差・所属添字・支持エッジを保持。`area`は未推定の0、`boundary`は予約欄のため、外形・観測面積として使用不可。
- 密度管理には観測領域だけの疎な粗セルを使用。平面ごとの基準接線を固定した面内セルで支持領域を表し、現在の元点で支持を更新し、辺の通過だけでは塗りつぶさず、支持点のない穴・曖昧なセルは保護。内部は確認済み支持セルの侵食で抽出。最初から全空間の細かいFVGを再構築しない。
- 状態は平面仮説、支持セル、安定観測時間、最終観測時刻、保護理由、粗密目標。広がりの変化で動く重心そのものや、移動するGNGノード座標だけを静止判定に使用しない。現在入力の確認は学習に選ばれた点だけに依存させない。
- [AiSGNGComponent](../../../ais_gng_cpu/src/ais_gng/src/ais_gng_component.cpp)は`gng_exec()`後に直接平面を抽出。抽出結果と同じmapから次フレーム用の軽量な制御情報を作成し、現在入力で失効判定後にコアへ適用する案。ROSトピックの非同期受信を必須としない。
- `node_indices`は当該mapの添字。次フレームへ生の添字を持ち越さず、空間領域と必要に応じてノードID・生成フレームで対応。ノードの削除・ID再利用を検出。
- [GNG実行順](../../../ais_gng_cpu/src/gng_cpu/src/cpu/gng.cpp)に合わせ、観測確認は追加判定前、整理は学習後・クラスタリング前の更新区間へ配置。ノード削減だけを理由に平面が消えて再増殖しないよう、直近の平面状態を現在の実測支持で検証しながら保持。現在入力の支持がなければ粗密制御を継続しない。
- 設定候補は機能ON/OFF、大きさ、平面品質・位置変化・法線変化の許容、確認時間、有効期限、目標間隔、境界保護幅、観測維持の学習枠、局所ノード予算、フレーム当たり削減上限。初期値は既存bagの分布確認後に決定。初期実装の既定はOFF。
- 更新対象は観測セル・変更ノードを中心とし、全入力×全平面の総当たりは避ける。元点の平面確認と履歴更新は追加コストとして独立計測。今回の設計だけで全入力照合時間の短縮は保証しない。

**初期検証の順序**

1. 削減を行わない診断モードで、平面内部／保護領域／静止候補を表示・集計。交差点の路面に適用され、車・人・段差・穴が保護されることを確認。
2. 比較用に固定した乱数系列・同一入力で「現行」「学習配分のみ」「追加抑制も適用」「段階削減も適用」を比較。学習結果の同一性ではなく配分と形状保持を評価。学習上限は固定し、コアの全入力照合・学習・整理・平面抽出・全体の時間を分離。
3. 静的平面、斜面、細長い面、穴、段差、停止中の車・人、平面上への新規物体出現・退出、遮蔽、クラスタ分割・統合、TF欠落・bagループを検証。
4. 指標は対象内部のノード占有数、領域別学習回数、被覆と平面残差、成分数、境界・人車のノード保持、出現後の通常密度復帰時間、定常時の追加／削除数。全体ノード数だけを成功条件にしない。

未確定: 支持セルの分解能と侵食幅、静止背景の判定値、維持可能な粗さ、代表選択と接続の局所検査範囲。初期診断と合成ケースで具体化する内容。今回は設計文書のみで、ノード削減・速度向上の実績なし。
