# 2026-09-23 Spatial Tree版GNGの比較

## 実装と分離

利用者の指示に従い、現行GNGを`ais_gng_cpu/experimental/gng_spatial_tree/`へコピーして新規作成。元のcugng.cpp・cugng.hpp・CMakeLists.txtへ一時的に追加した今回分は除去。従来の未コミット修正は保持。稼働中GNGとインストール済みライブラリは置換なし。

コピー側のSpatialTree版はワークスペースのSpatialTree::AdaptiveTreeを利用。getDownSamplingGrid・getMinGridの候補探索をAABB検索へ変更し、ノード追加・移動・削除で索引を更新。探索結果を従来のセル走査順へ整列。27セル相当の探索領域、セル容量、距離判定、ラベル付与、寿命更新、入力点を維持。木の索引更新省略なし。グリッドを完全撤去する版ではない。

## 計測条件

Intel Core i7-14650HX、既存Docker、Release -O3、両版で同じコンパイル条件。外部SpatialTreeヘッダーは現行ワークスペース版。
Macnica bagの/lidar_points先頭30フレーム（約16万点）を50回入力、先頭10回を除く40回を集計。各版3試行。実行順はgrid→spatial→spatial→grid→grid→spatial。

設定は計測開始時のat128.yamlをスナップショット。node.num_max=20000、learning_num=4000、grid=0.5、voxel_grid_unit=0.1、interval=[0.1,0.4,0.4,0.1]、X/Y±200 m、Z -5〜10 m。作業中に利用者側で変更されたYAMLは書換えなし。

学習乱数とLPFの時間刻みを両版で固定（比較専用、0.1秒）。元点群はセンサー座標をそのまま入力。ROS・TF変換・viewer描画・外部Torch分類を除外。内部GNGクラスタ処理は含む。測定対象はAPI入力コピー、gng_exec、出力取得。グラフのハッシュ計算・bag読込は時間外。

## 結果

| 試行 | グリッド版 gng_exec平均 ms | SpatialTree版 gng_exec平均 ms |
|---|---:|---:|
| 1 | 109.16 | 614.17 |
| 2 | 110.08 | 620.45 |
| 3 | 111.87 | 616.43 |
| 3試行平均 | 110.37 | 617.02 |

入力・出力APIを含む平均は113.04 ms対619.70 ms。GNG本体で約5.59倍の実行時間。今回の条件と実装では高速化なし。

各試行50フレームすべてでノードID・座標・法線・rho・label・生成フレームとエッジ列のSHA-256が一致（合計150/150）。最終ノード19,925、エッジ51,660で一致。これは比較したグラフ項目の一致であり、全内部状態・任意入力での同値性を保証するものではない。

AABB探索、候補の順序復元、移動時の木更新が追加される一方、従来の27セル直接参照を置換。この負荷が遅くなる要因候補。関数別の寄与率は未計測。他の木構造方式・探索意味を変える高速版の性能を示す結果ではない。

## 検証・再現

両版8件ずつ、計16件のAPIテスト成功。初回は寿命テストへの必須引数不足で両版が失敗し、登録修正後に全件成功。独立コピー前の暫定ビルドはヘッダーパス・テストへのinclude伝搬で失敗し、最終版は独立CMake構成で解消。

[ソースとコマンド](../../../ais_gng_cpu/experimental/gng_spatial_tree/README.md)、[設定・集計結果](../../../benchmarks/gng_spatial_tree_20260923/)。生JSON・ビルドログ・比較用共有ライブラリはGit管理外の`artifacts/gng_spatial_tree_20260923/`にローカル保管。共有ライブラリは比較専用の乱数・時間固定版。

実行コマンドはREADME記載のcmake・ctest・`timeout -s INT -k 5 90 python3 .../benchmark.py`。ライブラリをgrid/spatial、出力名を各3試行分へ変更。すべての計測・テストプロセスは終了。一時ビルドと一時ログを削除し、成果物だけ保持。既存GNGの停止・再起動なし。作業中の利用者側のGNG再起動・他プロセス負荷は隔離していないため、絶対時間にはその影響を含む。
