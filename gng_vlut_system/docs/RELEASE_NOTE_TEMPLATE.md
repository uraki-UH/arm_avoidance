# リリースノートの書式

この書式は報告作成を明示された場合のもの。編集・検証ごとの報告作成を要求しない。通常は採用済み変更に関係する既存の仕様・手順だけを更新。

「項目名: 値」を基本とし、補足は体言止め。小変更は5〜10行、通常は10〜30行が目安で、下限なし。重要な条件が多ければ超過可。以下は書式例で、項目・値は実際の変更と検証に置換。

```md
# YYYY-MM-DD - 対象と変更結果

変更:

- 設定項目数: [変更前] 個 → [変更後] 個
- 重複設定: 統合

結果:

- 単体試験成功数: [成功数] / [総数] 件
- 実機動作: 未検証

条件: [比較対象・入力・設定]
詳細: [仕様・再現手順](関連する既存文書へのリンク)
```

## 書き方のルール

- 該当しない項目や「変更なし」だけの記述は省略。節・表は比較が読みやすくなる場合だけ使用し、長い1行への詰め込みで行数を減らさない。
- 数量は数値と単位、定性的な変更は「削除」「統合」などの状態語。表でも数値列と評価・理由を分離し、項目名で意味を明示。表現の詳細は[文書更新スキル](../../skills/maintain-project-docs/SKILL.md)を参照。
- 同じ作業の続報は既存ノートへ統合。経緯・仕様・数値表・コマンドの重複は削り、既存の正本へリンク。短縮のためだけの別冊追加は不要。
- topic・parameter・message・launch引数の変更は最終値と移行方法を保持。数値は区間/全体、実測/推定、比較条件を区別。
- 未解決の失敗・未検証・最終判断に影響する制限は保持。修正済みの一時エラーや途中の測定値は、判断の根拠として必要な場合以外は省略。必要な再現コマンド・試験終了状況は正本へ集約。
- 仕様・設計・再現手順の必要な詳細は削らない。過去の報告は対象日と当時の制限を保持し、現行仕様・未完了タスクと区別。
- まとめ版も結論と重要な制限を中心に、詳細は個別記録へリンク。`progress.md` は1件1〜2項目の結果と根拠リンクだけで、本文を複製しない。
