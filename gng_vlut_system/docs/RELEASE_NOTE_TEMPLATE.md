# リリースノートの書式

結論を先に、読む人の判断に必要な情報だけを記載。小変更は5〜10行、通常は10〜30行が目安で、下限なし。重要な条件が多ければ超過可。

```md
# YYYY-MM-DD - 対象と変更結果

変更結果を1文で記載。

- 影響：利用者に変わる点。移行が必要なら旧→新の設定・操作。
- 検証：条件・結果。数値には対象と単位。
- 制限：失敗・未検証・互換性上の注意。

詳細：[仕様・再現手順](関連する既存文書へのリンク)
```

## 書き方のルール

- 該当しない項目や「変更なし」だけの記述は省略。節・表は比較が読みやすくなる場合だけ使用し、長い1行への詰め込みで行数を減らさない。
- 同じ作業の続報は既存ノートへ統合。経緯・仕様・数値表・コマンドの重複は削り、既存の正本へリンク。短縮のためだけの別冊追加は不要。
- topic・parameter・message・launch引数の変更は最終値と移行方法を保持。数値は区間/全体、実測/推定、比較条件を区別。
- 検証の失敗・未検証と試験プロセスの終了状況は省略しない。起動コマンドは再現資料へリンクし、正本がなければ本文に記載。
- 仕様・設計・再現手順の必要な詳細は削らない。過去の報告は対象日と当時の制限を保持し、現行仕様・未完了タスクと区別。
- まとめ版も結論と重要な制限を中心に、詳細は個別記録へリンク。`progress.md` は1件1〜2項目の結果と根拠リンクだけで、本文を複製しない。
