# CPU版GNGの高速化実装と処理時間の比較（2026-09-24）

2026-09-23〜24の保存済み検証資料とフレーム別計測結果を整理した報告。対象は通常CPU版と独立実験版。本書作成時の再ビルド・再計測はなく、内訳は既存データから再集計。

## 1. 現時点の結論

- **本番の全体時間に効果を確認した変更**は、空きノードID探索の改善、入力の基数ソート、探索用データの連続配置、実在エッジだけの保存。効果の大きさは入力voxel幅に依存。
- **特定区間に効果を確認した変更**は、法線・曲率の座標参照と差分再利用、孤立候補管理、エッジプールの直接走査。区間の短縮率と全体の短縮率は別の値。
- **採用を見送った変更**は、重点候補XYZコピーの元番号／区間参照化、移動ノードを追跡する距離差分更新、最小ヒープによる空きID管理、CPU固有命令の追加。無効果と断定したものだけでなく、別案より効果が小さかったものも含む。
- **現在の最大の負荷は学習前の全入力照合**。最新比較の変更後は、voxel 0.1 mで照合66.182 ms／全体94.004 ms、0.5 mで照合10.689 ms／全体32.807 ms。
- tree方式と最小構成は独立実験版。特に全点照合・重点学習・クラスタを省いた版の時間は、本番と同機能の高速化率として扱えない。

全施策の適用前と現在版を、同じセッションで直接比較した累積高速化率は未計測。以下の表は各変更時点の同条件比較であり、短縮率の加算や別の表の端点同士による累積率計算は不可。

## 2. 測定条件と用語

### 本番相当の比較条件

| 項目 | 条件 |
| --- | --- |
| データ | Macnica交差点bag `algo_0000_ros2/algo_0000_ros2.db3` の `/lidar_points` |
| 入力 | 約16万点／フレーム、上限20万点。YAML範囲と有限値確認を維持 |
| GNG | ノード上限20,000、学習4,000回／フレーム、`node.grid=0.5 m` |
| 比較パラメータ | `input.voxel_grid_unit=0.1 / 0.5 m` |
| ビルド | Release、`-O3 -DNDEBUG`、本番で既存のLTOを維持 |
| 実行 | 既存Docker内、CPU 0固定。別プロセスの負荷変動あり |
| 通常の集計 | 300フレーム＋100フレーム×2試行。各試行の共通区間［50, 100）の平均の3試行中央値 |
| 基数ソートの採用評価 | 6シード×200フレーム。先頭50除外後の各シード平均を、さらに6シードで平均 |
| 再現性 | 比較コピーだけ乱数と時間刻みを固定。本番は通常の乱数・実時間 |

基数ソートの6シード比較では観測支持を有効化。他の表と実行時期・追加機能条件まで同一ではない。設定の正本は各検証資料に保存したYAMLであり、稼働中ROSの設定をそのまま計測した値ではない。

本書の「全体」はC APIへの点群転送＋`gng_exec()`＋グラフ出力取得。bag読込・逆シリアル化・ROS通信・TF・ROS側の平面／曲面処理・人車分類器・Viewer描画は計時外。表の「GNG内部クラスタ」はコア内のクラスタ処理であり、ROS側の平面・曲面フィッティングとは別。

「全入力照合」の対象は、voxel有効時には全占有セルの重心、voxel無効時には全保持点。学習で選ぶ4,000点だけを照合する処理とは区別。

疎エッジの1.8 MBは、2万ノード時のエッジ関連配列の予約容量。グラフ全体やROSノード全体のメモリ量ではない。計測用Python込みの初期化直後RSSは約1,984.6→78.5 MiB。bag事前読込後の最大RSSとも別の指標。

基数ソート以外の上記採用比較では、固定条件で座標・グラフ・ラベル等の一致を確認。基数ソートではセル内順序の変化により、浮動小数点加算順だけでなく重点候補から実際に選ぶ点も変化。同一シードのグラフ完全一致は保証しない。6シードの0.2 m被覆率の平均差は+0.0894／−0.0588ポイントで、当該bagのシード間ばらつきより小さかった。観測代表点も変化するため、単なる量子化誤差だけの変更ではない。[採用判断][b]

| 移動ノードを追跡した辺の距離差分更新 | 保守2.285→2.249／1.937→1.903 | 短縮が約0.03 msと小さい。追跡を伴わないエッジプール直接走査を採用。差分更新そのものが常に遅いという結論ではない。[E][e] |
| 探索配列の同期再利用だけ | 全体96.608→99.490／34.438→34.640 | 単独では全体短縮未確認。最終版では同じ座標配列を辺の距離計算にも再利用し、合成の保守区間を改善。[E][e] |
| クラスタ管理だけ | クラスタ6.028→6.067／6.458→6.258 | 0.1 mでは短縮未確認。合成版には採用したが、主要な高速化要因とは断定しない。[D][d] |
| 最小ヒープによる空きID管理 | 最小tree版で12.29→8.92。開始位置保持は8.56 | 効果はあったが、単純な開始位置保持より遅く、標準構成への採用見送り。[最小版][runtime] |
| CPU向け命令選択 | `-march=native -ffp-contract=off` の短縮率が約−2.4〜+0.8% | 明確で一貫した改善なし。標準OFF。[最小版][runtime] |
| 木に置き換えるだけ | 固定順8分木112.51に対して比較grid104.26 | 8分木化だけでは高速化せず。bsp3dへの変更と、全入力への照合回数は別に評価。[最近傍比較][nearest] |

## 7. tree方式・最小構成の実験

### 7.1 探索方式の変更

以下はGNG本体時間。行ごとに比較セッションが異なり、別行をつないだ累積率計算は不可。

| 比較 | 変更前→変更後 | 効果・制限 |
| --- | ---: | --- |
| AABB範囲候補収集→厳密2近傍 | 617.50→196.56 ms | 候補列挙・候補整列を削減。ただし寿命・ラベル判定の対象も最近傍2ノードへ変化 |
| 子セルの距離順ソート→固定順探索 | 196.56→112.51 ms | この2方式の実bagグラフ150/150一致。比較grid104.26 msよりは遅い |
| 固定順8分木→bsp3d | 112.04→95.50 ms | 約14.8%短縮、実bagグラフ150/150一致。同じ比較のgridは103.94 ms |
| 固定ノードgrid撤去だけ（0.1 m） | 103.67→102.06 ms | 速度改善は小さい。セル収容制限等の挙動は変化 |
| 固定grid撤去＋照合回数制限（0.1 m、短い比較） | 元grid112.84→76.03 ms | 高速化あり。全域探索・接続・重点学習の頻度と配分が変化 |
| 同じ回数制限版（0.5 m、短い比較） | 元grid53.46→73.61 ms | 約15,668入力セルに対して探索上限16,000回。照合削減がなく観測索引等の追加費用が増加 |
| 回数制限版（0.1 m、連続300フレーム） | 元grid114.94→83.47 ms | 平均は27.4%短縮、p95は128.10→133.61 msへ増加 |

初期tree比較は先頭30フレームを50更新へ再利用し、先頭10更新を除外。CPU固定なし。AABB版は1試行、その他の上記短い比較は3試行。最近傍2ノード版とgrid版は判定の意味が異なり、bsp3dの汎用的な上位互換性や全入力での同じグラフを示す結果ではない。[最近傍比較][nearest]・[bsp3d比較][bsp]・[回数制限版][sampled]

### 7.2 入力voxelを省いた最小版

同じ比較セッションの本体時間は、元CPU208.30 ms、回数制限版136.32 ms、元点直接学習版21.40 ms。ただし最小版は全点事前照合・重点候補・全観測寿命リセット・クラスタ等を省略し、平均ノード数19,880→8,441、原点以外の0.2 m被覆率76.75→52.34%、連結成分92.4→425.0へ変化。大幅な短縮を「同じ結果のまま約10倍」とは表現できない。[最小版検証][minimal]

同じ最小学習処理で入力と探索だけを切り替えた別比較：

| 入力 | tree本体 | grid本体 | tree入力整理 | grid入力整理 |
| --- | ---: | ---: | ---: | ---: |
| 生点群 | 11.30 | 11.15 | 0.98 | 0.99 |
| 入力voxel 0.1 m | 26.37 | 24.98 | 12.10 | 11.81 |
| 入力voxel 0.5 m | 22.47 | 21.37 | 8.92 | 8.64 |

全条件で学習4,000回。入力voxelで候補数が減っても、この最小版の学習時探索回数は減らない。学習確率が元点密度基準から占有セル基準へ変わり、実ノード数や被覆も変化。[最小構成の比較][minimal_comparison]

### 7.3 最小版の実装最適化

空きID開始位置保持、LTO、重心走査統合を組み合わせた連続300フレーム比較。単位は本体ms。

| 条件 | 基準 | 出力一致を確認した合成版 | さらに基数ソート |

| 生点群＋tree | 11.20 | 6.43 | 対象外 |
| 生点群＋grid | 9.79 | 5.45 | 対象外 |

LTO単独は短い生点群＋tree比較で12.29→10.05 ms。本番はこの検証より前からLTOが有効なため、「今回本番へLTOを追加して得た効果」には含めない。最小版の基数ソートも現在は標準ONだが、表の出力一致版とは区別。[実装・全結果][runtime]

## 8. 現在残っている負荷と評価範囲

最新採用版Eの入力照合は、全体に対する比率の目安で0.1 m約70.4%、0.5 m約32.6%。この区間は最近傍の取得だけでなく、未被覆領域へのノード追加、接続・辺の寿命更新、観測されたノードの寿命リセット、重点学習用ラベル判定を含む。4,000学習点だけの処理とは異なる。

voxel 0.5 mでは照合以外に、GNG内部クラスタ約5.316 ms、学習約4.473 ms、入力voxel整理約4.427 ms、法線周辺約3.433 msが残る。学習回数を保ったまま小さい区間だけを改善しても、全体の短縮量は限られる。

ノード寿命の全体走査、法線・曲率の全有効ノード更新は残存。`eta_decay_rate < 1` の場合の学習係数減衰も、元の乗算順を保つ全体走査。設定済み比較条件は1.0。このCPU実装の学習経路には、標準的GNGの「最大積算誤差で分割・全ノード誤差を一括減衰」の処理自体がなく、今回の削減対象ではない。[実装範囲][e]

`input.voxel_grid_unit` の拡大は全点照合の回数に影響するが、入力の表現・候補配分も変える。`node.grid` はノード探索・格納の別設定。設定変更による時間差を、同条件の実装高速化に合算しない。

平面・曲面OFFに伴う不要ノード・購読の抑止は実施済み。ただし機能停止による軽量化であり、本書のコア高速化率には合算していない。[関連変更](releases/2026-09-23_gng_clustering_topics.md)

bag再生の約4.2 GBの先読み待ちは、フレームごとのGNG計算時間とは別の起動遅延。`--read-ahead-queue-size 20` による変更後の起動時間は未計測であり、高速化実績には含めない。[起動調査](progress.md#2026-09-24-gng再起動後の入力待ち調査)

## 10. SpatialTree整理とbsp3dへの移行

本書作成後、ユーザーの移行指示に従い、目標選択の索引もbsp3dへ統一。double座標の閉区間AABB検索を追加し、座標が同じ場合の索引再利用・TF逆変換・元セルによる再判定を保持。旧GNG比較パッケージの8分木方式、共通 `SpatialTree/`、bsp3d内の重複8分木実装と旧生成スクリプトを削除。

bsp3dには葉の座標キャッシュ、部分木の件数管理、領域境界を管理する祖先への直接移動が既存実装としてあり、旧8分木の構造を追加移植する根拠はなし。不足していた範囲検索を追加。初期構築の一括処理案は比較で遅くなり不採用。

初回の実GNG18,729座標に対する範囲検索1024回は0.664→0.461 ms、構築は1.371→4.420 ms。別プロセスの目標選択比較では約0.075〜0.116 ms増加したが、変更しない全走査基準も変動しており、その差をbsp3dだけの退化とは断定しない。

同日追加で、特徴量・出力ID参照表の再利用と、bsp3dの移動・追加・削除による差分索引へ変更。座標変更ごとの全再構築は呼出し側の実装上の制限であり、bsp3dに必須の動作ではなかった。同一プロセス比較ではロボット保存座標10,801点・候補20件の静的選択1.221→0.254 ms、人工的な全点移動条件の更新＋選択2.422→0.714 ms。最終92,610組の出力一致を確認。[新仕様・制限](releases/2026-09-24_goal_selection_efficiency.md)、[全比較値・再現条件](../../benchmarks/goal_selection_efficiency_20260924/README.md)。

初回構築は依然増加し、合成平面の全点移動には旧版より遅い条件あり。今回の結果は目標選択の処理であり、CPU GNG学習全体の高速化率には含めない。
