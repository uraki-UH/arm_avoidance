# CPU版GNGの高速化報告（2026-09-24）

## 1. 報告の要約

**高速化効果を確認した変更**

- 空きノードID探索・voxel重心計算の改善
- 入力の基数ソート
- 探索用データの連続配置
- 実在エッジだけの保存

効果の大きさは入力voxel幅に依存。

**特定の処理区間で効果を確認した変更**

- 法線・曲率計算の座標参照改善と差分再利用
- 孤立ノード候補の管理
- エッジプールの直接走査

処理区間の短縮率と、全体の短縮率は別。

**採用を見送った変更**

- 重点候補XYZコピーの元番号・区間参照化
- 移動ノードを追跡するエッジ距離の差分更新
- 最小ヒープによる空きID管理
- CPU固有命令の追加

**現在のボトルネック**

学習前の全入力照合。入力voxel幅が小さいほど照合対象が増加。

**独立実験**

tree方式と最小構成を実装・比較。最小構成は全点照合・重点学習・クラスタなどを省略しており、本番と同機能での比較ではない。

**処理時間：最新比較の変更後（ms／フレーム）**

| 処理 | voxel 0.1 m | voxel 0.5 m |
| --- | ---: | ---: |
| 入力転送 | 1.043 | 1.048 |
| 入力voxel処理 | 4.273 | 4.427 |
| 全入力照合・重点候補・対応整列 | 70.315 | 11.466 |
| うち入力照合 | 66.182 | 10.689 |
| 学習4,000回 | 5.517 | 4.473 |
| 法線・曲率・ラベル | 4.662 | 3.433 |
| グラフ保守 | 1.565 | 1.284 |
| GNG内部クラスタ | 5.164 | 5.316 |
| グラフ出力取得 | 1.334 | 1.205 |
| **全体** | **94.004** | **32.807** |

各項目を独立に集計しているため、合計と全体は厳密には一致しない。「うち入力照合」は内数。

## 2. 測定条件

| 項目 | 条件 |
| --- | --- |
| データ | Macnica交差点bag `algo_0000_ros2/algo_0000_ros2.db3` の `/lidar_points` |
| 入力 | 約16万点／フレーム、上限20万点。YAML範囲と有限値確認を維持 |
| GNG | ノード上限20,000、学習4,000回／フレーム、`node.grid=0.5 m` |
| 比較パラメータ | `input.voxel_grid_unit=0.1 / 0.5 m` |
| 実行環境 | Releaseビルド、Docker内、CPU 0固定 |
| 上表の集計 | 各試行のフレーム区間［50, 100）の平均を求め、3試行の中央値 |

計測範囲は、C APIへの点群転送＋`gng_exec()`＋グラフ出力取得。bag読込・ROS通信・TF・ROS側の平面／曲面処理・人車分類器・Viewer描画は計測時間外。

各施策は変更時点ごとの比較であり、全施策を通した累積短縮率は未計測。

計測資料：[各実験の一覧](../../benchmarks/README.md)、[最新比較の条件・結果](../../benchmarks/gng_incremental_updates_20260924/README.md)。
