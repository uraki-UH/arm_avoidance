## 候補

### 評価指標の flat 構成整理

- `GraspCandidateMetric` は flat なまま維持する。
- 可操作性は `position` / `rotation` / `dynamic` の 3 系統へ分ける候補を残す。
- `condition_number`、`min_singular_value`、`singular_values` のような派生・中間量は固定metricとして増やさず、必要なら楕円体パラメータを基本表現に寄せる。
- 経路候補については `path_cost` のような単一コストへ早期圧縮せず、経由ノード ID 列と関節角度列を優先して保持する。

### 候補ポーズと GNG ノードの関係

- `grasp pose candidate` と `goal GNG node` は 1 対 1 に潰さず、多対多で扱う候補を残す。
- `pose_id` と `goal_node_id` の対応は、後段で総合評価しやすい形式へ整理する。
- 同じ GNG ノードが複数の把持候補から参照される前提で、逆引き情報も保持できるようにする。

### 把持ボクセル照合の3次元姿勢生成と物体分離

- 現在の直接照合は明示的な`orientation_rpy`または固定roll/pitchとyaw分割を使う。局所ボクセル共分散、GNG法線、接触面法線のどれから3次元姿勢を生成するか比較する。
- 連結成分、時間追跡、semantic情報を使って物体候補ボクセルを個体ごとに分離し、候補Poseへ一意なobject IDを付ける形式を決める。
- 実点群で候補数と処理時間を計測し、直接照合の上限を超える場合は接触posting indexによる逆引きへ切り替える。

### 人共存環境における把持候補の安全ゲート

- 現段階は記録rosbagで妥当な把持位置候補を生成できるかを評価対象とし、候補生成を実ロボットの把持許可・実行へ直結しない。
- `topo_voxel_ids`は占有・構造証拠として保持し、`UNKNOWN` / `WALL`を候補許可の根拠にしない。別途、作業者指定または物体認識で**肯定確認した対象ROI内**だけを出す`grasp_candidate_voxels`の入力・出力形式を決める。
- RGB-Dの人検出・追跡、およびGNGの局所的な一貫移動を`person_exclude` / `dynamic_exclude`として候補拒否に使う。除外は占有地図の削除ではなく候補の保留とし、誤検知後に再評価できるようにする。
- 実機で把持実行を行う前に、人または未識別物が危険領域へ侵入した際に接近・把持を停止できる、認識系から独立した安全系とリスクアセスメントを整備する。通常の点群・GNG判定を安全停止の唯一の根拠にしない。

### 関節 wraparound の関節種別対応

- 全関節共通の `use_wraparound` と `virtual_joint_state_use_wraparound` は廃止する。
- URDF で `continuous` の関節だけ角度差を `[-pi, pi]` に正規化し、制限付き `revolute` 関節には適用しない。
- `virtual_joint_state_driver_node` と `target_joint_state_executor_node` の判定を共通化する。
- ToPoDualArm は `continuous` 関節を持たないため、現状の wraparound 対象は 0 関節とする。
- `continuous` の `+179/-179` 度と制限付き `revolute` の `+2.5/-2.5` rad をテストする。

### 占有分布に基づくノード配置学習と3値論理による無衝突保証

手法の中核主張になりうる論点。先行研究 Steffen et al. 2022 (arXiv:2207.03959) が「ノード間の補間区間は無衝突を保証できない」「障害物との距離尺度を持たない」と明記している部分への回答にあたる。

**1. 3値論理による保証**

障害物側、または FK 占有ボクセル側を膨張させる(ミンコフスキー和として等価)ことで、ノード状態を3値にする。

- 安全: 膨張後の障害物とも衝突しない
- 危険: 膨張後とは衝突するが実障害物とは衝突しない境界帯
- 衝突: 実障害物と衝突

これにより「安全ノード間の補間は無衝突」が保証される。成立条件は、膨張量が接続ノード対の占有集合の対称差の上界以上であること。命題として定式化して示す。

**2. 占有分布に合わせたノード配置**

一様膨張は最悪ケースのノード対に律速されるため非効率。C空間で一様に配置するのではなく、3次元占有分布に合わせて配置すると膨張量が全域で最小かつ均一になる。

計量は手先ヤコビアン(`J^T J`)ではなく、**占有ボクセル集合の差**で直接定義するのが正確。手先ヤコビアンだと冗長姿勢(肘の位置違い)を誤って畳んでしまうため。占有で定義すれば全身が自動的に入り、衝突判定と同一の量で計量が定まる。`robot_voxelizer` の計算がそのまま使える。

**3. ノード数はむしろ減る**

占有が変わらない自由度方向は距離ゼロとなり単一ノードに畳まれる。例: z軸方向に伸び切った姿勢での z軸回転は占有を変えないため、その自由度領域を1ノードが担当する。位相的つながりも、障害物による占有変化の反映も破壊しない。特異点近傍でノードが増えるわけではない(逆)。

**4. 膨張情報のボクセル埋め込み**

大域的に単一の膨張半径を持つ代わりに、ノードまたはボクセルごとに必要な膨張量を保持する。VLUT に1フィールド足すだけで実行時コストは増えず、膨張という前処理自体が不要になる可能性がある。

**5. 階層構造**

タスク空間(3D占有分布)の層と、各セルに紐づく C空間ノード群の層に分ける案。これは既存の「候補ポーズと GNG ノードの多対多」の論点と同じ構造であり、VLUT の多対多関係を学習された形で明示することになる。1層でやる場合は GNG の勝者決定と挿入基準を上記の計量に置き換える。

**6. 所要時間はノード内選択で最適化する**

畳まれた自由度は情報の損失ではなく、安全性に影響しない最適化変数として明示的に取り出された状態にあたる。ノード内の姿勢はすべて占有が等価すなわち衝突判定が等価なので、どれを選んでも安全性は変わらない。よって軌道生成時に、その中から所要時間が短い姿勢を選べばよい。

関心事が層で分離される。

- 離散グラフ(ノード列): どの占有領域を通るか — トポロジーと安全性
- ノード内の連続選択: 各領域内でどの姿勢を取るか — 所要時間と滑らかさ

C空間で一様にノードを置く手法ではこの自由度がノード列に埋もれるため、同じ最適化ができない。畳むことが利点になる点として主張する。

**検討が必要な点**

- ノードの等価類をどう表現するか。GNG ノードが持つのは重みベクトル1本で領域は陽に保持されない。案: (a) 学習時にそのノードへ割り当たった姿勢群を保持(BMU履歴)、(b) ノード重み近傍の零空間基底を保持、(c) VLUT の逆引きから占有パターン経由で復元。(c) が使えれば追加コストが最小。
- 計量が姿勢 `q` に依存するため線形変換では吸収できない。標準 GNG からの変更点として論文に明記する必要がある。
- 学習時に占有計算を繰り返すため、オフライン学習のコストが増える。事前計算やキャッシュでどこまで抑えられるか。
- 「ノード数がむしろ減る」ことの実測がまだない。C空間一様配置との比較数値が必要。

### ノード状態フラグの責務整理

`Status` の3つのフラグの役割が混ざっている。挙動が変わる修正のため、実機検証の予定と合わせて計画する。

| フラグ | 本来の意味 | 設定元 |
|---|---|---|
| `active` | 構造上ノードが存在するか(削除予定のマーク) | GNG 管理側。オフライン学習時のみ |
| `self_collision_free` | 静的な自己干渉の有無 | 自己干渉プロバイダ。オフライン学習時に確定 |
| `is_colliding` | 動的な環境衝突の有無 | 障害物ラベル、VLUT。実行時 |

**問題1**: `topological_map_avoidance_node.cpp` が環境障害物のラベル反映時に `self_collision_free` を書き換えている(該当箇所に FIXME 済み)。障害物が消えると `true` に戻すため、元々自己干渉していたノードが安全と誤判定されうる。実害の有無は、学習時に自己干渉ノードを GNG から除外しているかどうかで決まる(未確認)。

**問題2**: `gng_self_collision_provider` は `self_collision_free` にしか書かないが、`gng_geometric_self_collision_provider` は `is_colliding` にも書く。プロバイダ間で挙動が違う。

**問題3**: `active` は実行時には常に `true`。オフラインで無効化されたノードは `removeInactiveElements()` で削除済みのため、ロード後のノードは全て `active == true` になる。実行時の読み出し39箇所は常に true を確認しているだけの可能性が高い。ただし `boundary_node_classifier` が「隣接ノードが無効」を境界の定義に使っているため、単純な削除は不可。

**方針案**: 削除ではなく責務の分離。実行時の判定からは `active` を外し、`self_collision_free` は実行時に書き換えない。判定は `!self_collision_free || is_colliding` で無効、の形に揃える。

### 把持候補近傍の局所密度を制御する GNG

- 現行の点群 GNG は `node.interval`、`node.grid`、`edge.age_max`、入力ボクセルサイズなどが絶対的な長さ・回数であり、RGB-D、LiDAR、物体、作業環境のスケールごとの再調整が必要。
- 把持位置推定では、壁面や背景まで一様な密度で学習する方式ではなく、把持候補・物体境界・接触予定面の近傍へノード密度を配分する方式の検討。
- 局所密度の基準、ノード予算の配分、スケール変更時のグラフ連結性・候補分解能・処理時間を比較する評価設計の作成。
