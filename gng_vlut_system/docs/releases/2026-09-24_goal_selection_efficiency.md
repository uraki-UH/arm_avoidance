# 2026-09-24 - 目標選択の参照表再利用と空間索引の差分更新

## 1. 要約

目標選択の毎周期の全体走査を削減。座標が変わるたびに索引を破棄していた処理を、bsp3dの移動・追加・削除APIによる差分反映へ変更。

- 特徴量は受信時にID参照表を更新し、選択周期では再利用。
- 選択IDに対応する全ノードを直接収集。重複ID・元配列順・同点順位を維持。
- 索引要素のアドレスをdequeで維持し、変更座標だけを更新。点の追加・削除・無効化も差分反映。
- TF・メタデータ更新では空間索引を再利用。全体再構築の廃止と、bsp3d内部の分割・部分木再構成は区別。

- 移動・追加・削除・並べ替え・非有限座標の回帰、参照表の更新と重複IDの回帰。
- 同一プロセスの7方式比較、保存ロボット座標を含む3入力、7更新条件、隔離ROSでの受信更新検証。

- 位置が少し変わるだけでも全索引を再構築する目標選択側の実装を修正。bsp3d自体に毎回再構築する制約はなし。

**削除**

- 選択周期での全特徴量hash表再構築と、出力ノード抽出の全ノード走査。
- 座標変化を理由とした無条件の索引全破棄。

## 2. 条件・検証

同じ入力に対する選択ID・map・出力順を維持。初回構築後、静的マップと移動ノードの両方で索引を再利用。旧8分木への復帰なし。

ロボット保存座標10,801点・候補20件・3試行中央値で、旧8分木＋元選択に対して静的選択1.221→0.254 ms、全点移動の更新＋選択2.422→0.714 ms。30Hz配信／5Hz選択を想定した6回受信＋1選択の処理量は1.955→1.756 ms。後2条件は人工的な更新条件であり、実環境の周期処理を再生した時間測定ではない。

変更なし。元CPU GNGの学習・YAML・スレッド構成の変更なし。

- 最終比較92,610組で全走査基準との出力一致。
- Release GTest15件、ASan/UBSan成功。差分索引の1,440範囲を全走査照合。
- 隔離ROSで受信・特徴量更新・順序変更・追加・削除・移動・候補消去の8ケース成功。通常Releaseビルド・インストール済み。
- [条件・全測定値・起動コマンド](../../../benchmarks/goal_selection_efficiency_20260924/README.md)。

**制約**

初期構築はロボット入力で0.735→2.843 msへ増加し、初回待ち時間の短縮ではない。参照表は18,729ノード・64bitで約1.14 MiB。合成平面20,000点・重複500点の全点移動では旧版4.415 msに対して4.863 msと増加。木の形状と移動分布による費用差があり、全条件での優位性は未確認。

旧8分木へ同等の差分更新を実装した比較ではない。座標以外のラベル・特徴量・候補は比較用の合成条件。実環境のROS処理全体の測定ではなく、ビルド・回帰・実座標の処理比較・隔離ROS検証の範囲。

検証プロセスは全終了、専用一時ビルド・ROSログは削除。既存ROS・bag13プロセスと3コンテナの状態を維持。
