# 2026-09-24 - 平面クラスタの整合化・局所スケール追従と内部小面の統合

## 1. 要約

長い平面の棄却・大量解放・固定距離上限による所属漏れと、内部小面の法線誤差による統合拒否を修正。
続報で、短い1本接続が継続する小断片の限定的な統合を追加。
凸包の重なりだけで統合する変更ではなく、GNG接続と平面残差による判定を維持。

- 面内縦横比だけでなく、短軸標準偏差と局所ノード間隔の比で面幅を評価。
  幅を保った長い路面は許容。直鎖・幅の乏しい帯の除外は維持。
- `enable_multi_edge_dist_relaxation=false`でも、既所属には保持用距離を適用。
  このフラグは取り込み・移動の複数接続による距離緩和だけに使用。
- 生成・取り込み・保持・統合の距離判定を局所エッジ長で正規化。
  `max_effective_spacing: 0.0`を既定値とし、絶対上限によるスケール追従の停止を解消。
  正値を指定した場合は、生成を含む各段階で任意の絶対上限を適用。
- 各ノードの局所間隔を隣接エッジ長の中央値へ変更。偶数本では小さい側の中央値を採用。
  取り込み・保持は対象ノード自身の間隔で判定し、長い橋エッジや粗い隣接面の影響を抑制。
- 相手の元平面との相互照合を、直接接続エッジの端点へ限定。
  小面の法線誤差を大平面の遠方まで延長して統合を拒否する条件を撤去。
  各側全体の統合後平面へのRMS判定を併用し、段差・傾斜小面・点密度差の誤吸収を抑制。
  各評価点群の局所間隔で正規化。端点統計の再利用により、対ごとの全点再走査なし。
- 通常の接続要求が2本の場合だけ、小断片・短い接続・厳しい残差・連続確認による1本接続の救済。
  確認履歴は永続クラスタID対で保持。接続消失・条件不適合・reset・空入力で確認回数を初期化。
  未所属点を挟む接続なしの別成分は対象外。
- 同一フレームの平面累積統計・求解結果を統合判定へ再利用。
  分割で所属が変わった場合は再計算。前フレームの古い位置の再利用なし。
- 生成時の要求接続が1本なら、探索元への接続を再利用し隣接の再走査を省略。

## 2. 条件・検証

| 項目 | 内容 |
| --- | --- |
| 新規設定 | `min_plane_width_ratio: 1.0`。CPU直結時は`plane_cluster.min_plane_width_ratio` |
| 面幅の意味 | `sqrt(λ2) / mean(spacing)`。縦横比条件とのOR。厚み制約は別途維持 |
| 距離比の既定値 | 取り込み`growth_residual_ratio: 0.15`、保持`retention_residual_ratio: 0.30` |
| 厚み・統合の既定値 | `max_normalized_cluster_residual: 0.15`、新規ROS設定`max_merge_side_residual_ratio: 0.15` |
| 固定距離上限 | `max_effective_spacing: 0.0`。0は上限なし、正値は上限[m] |
| 小断片救済 | `enable_fragment_merge: true`、`max_fragment_nodes: 30`、`min_fragment_merge_frames: 3` |
| 救済の幾何条件 | `max_fragment_edge_ratio_th: 2.5`（接続長 / 端点間隔の小さい側）、`max_fragment_residual_ratio_th: 0.10`（各側・接触部・統合後のRMS比）。通常の残差上限との厳しい側を適用 |
| 設定場所 | 共通`plane_cluster_incremental.yaml`。CPU直結時は`plane_cluster.`接頭辞。救済OFFで従来の接続条件へ復帰 |
| 維持した設定 | 通常の接続要求2本・残差悪化率・法線角度の設定値。要求3本以上への例外なし。ユーザーの`at128.yaml`は変更なし |
| メッセージ | 定義変更なし。`planarity`は従来値。`local_spacing`は各ノードの局所中央値の平均へ変更 |
| C++互換名 | `merge_smaller_side_residual_ratio`は名前を維持。各側の統合後RMSと接触部の相互RMSへ適用 |
| 互換性 | `ClusterOptions`・`ClusterStatistics`の追加フィールドにより利用側C++も再ビルドが必要 |
| 正解形状試験 | 平面38テスト成功。救済の連続確認・中断・添字変更・設定反映4件は変更前に失敗。段差・長い橋・大きい断片・要求3本の分離と拡大縮小を確認。既存の内部小面・傾斜面試験も成功 |
| 配布・起動 | ROS用Release反映済み。関連3スイート計118テスト成功。分離ドメインでCPU/平面ノードの設定宣言値を共有YAMLと照合 |
| ROS出力 | 720ノード長平面の3スケール、1,706ノード内部小面の統合・段差分離、169ノードの1本接続対の3フレーム目の統合を確認 |
| 実入力比較 | 接触部照合版→小断片救済追加。約19,144ノード、平面所属11,522.08→11,521.26点（60.187→60.182%） |
| 処理時間・総数 | CPU時間12.575→12.573 msでほぼ同等、クラスタ80.68→77.29。最終フレームの30ノード以下の断片61→56 |
| 従来動作 | 救済OFF時、全150フレームの非時間集計列が変更前と一致。ノード単位の完全一致検証とは別 |

時刻の異なるライブ画像との直接比較ではなく、bagから一度生成・保存した同じ入力での比較。
GUIの凸包描画は未変更のため、凹領域や穴を跨ぐ輪郭の包含表示は残る。
GNG接続がない別成分は、同じ平面に見えても無条件には統合しない。
街路の凹凸をどこまで同一平面として扱うかは距離比に依存。実bagの正解ラベルによる誤統合率は未検証。
変更前後で同じ入力150フレームを使用し、後半100フレームの平均を3試行の中央値で比較。
共有YAMLと配布バイナリへ反映済み。反映前から実行中のインスタンスは同じlaunchで再起動が必要。
試験ノードは停止済み。反映前バイナリのバックアップあり。
CTestの旧ライブラリ参照と、ROS試験のPython配列初期化エラーを修正後に再検証成功。
続報の初回ROSビルドで整数パラメータ型の不一致を検出し、型指定修正後にビルド・全テスト成功。
通常ビルド先の並行更新後も上書きせず、現行配布版で118テスト・ROS出力試験を再確認。
