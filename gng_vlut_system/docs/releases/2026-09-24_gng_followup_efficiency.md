# 2026-09-24 - CPU GNGの探索・クラスタ管理・エッジ保存の効率化

## Summary

4候補を独立・合成比較し、探索用連続配列、クラスタ管理、疎エッジ保存の3変更を本番採用。全体時間の3試行中央値はvoxel 0.1 mで101.209→91.937 ms、0.5 mで36.050→32.565 ms。約9.2%／9.7%短縮。

## Changed

- 探索用の座標・ラベルを連続配置し、入力順配列を再利用。バッチ内の追加・移動を即時反映。
- クラスタの作業配列再利用、所有権移動とswap、旧ID索引、投票の重複検索削減、空きROSID探索の継続。
- エッジ寿命・距離を実在辺の共有poolへ保存。上限20,000ノード時の配列容量は論理2 GBから約1.8 MB。探索用の追加配列は400 KB。
- 通常LiDARの重点候補XYZコピーは維持。元番号／区間参照も検証したが学習側の増加で短縮が相殺され、本番採用を見送り。

## Added

探索キャッシュ、クラスタID引継ぎ、疎エッジのdense参照比較、重点候補参照の回帰試験。独立比較ソースの生成、計測、全条件照合、原子的インストールと環境確認の再現スクリプト。

## Fixed

大きなNode構造体への反復参照、クラスタ所属配列の不要コピー、エッジ配列の二乗容量。

## Removed

ノード上限の二乗で確保するエッジ寿命・距離配列。

## Behavior Impact

全点照合、4,000回学習、入力フィルタ、重点配分、寿命更新、法線・曲率・クラスタ判定を維持。比較用コピーのみ乱数・dt固定。本番は従来の乱数・実時間。

内部C++クラス配置と`getEdgeIndex()`の数値は変更。直接利用する`gng_wasm_core`は再ビルド・native試験済み。公開C APIとNode構造は不変。ライブラリを原子的に反映し、次回GNG起動から有効。

## Topics / Params / Messages

変更なし。

## Verification

Release＋既存LTO、CPU 0固定、交差点bag、node.grid 0.5、ノード上限20,000。300フレーム＋100フレーム×2試行、2試行目は実行順反転。

- 本比較8,720フレーム・7,630組、事前probe1,000フレーム・800組で全照合項目一致。拡張機能の比較630組を含む。インストール済み実時間版の30フレームも成功。
- 本番CTest20件・追加API2件成功。共有CPUのWASM native試験1件成功。
- 疎エッジは24,096操作のdense差分比較とASan／UBSan成功。重点候補3方式各56ケース成功。
- 実際の引数なし`cb`で30パッケージが56.1秒で成功。WASMパッケージの符号比較等の警告あり、失敗なし。
- 初期化直後RSSは計測用Python込み約1,984.6→78.5 MiB。入力300フレーム事前読込後の最大RSSとは別の指標。
- 検証前に保存したViewer＋bagの9プロセスは終了時とPID・コマンド一致。初回読取にあったGNG3プロセスは保存ベースライン時点で既に存在せず、停止操作は実施なし。作成した検証プロセスは全終了、一時ビルドのみ片付け。

起動した主なコマンドは既存Docker内の`build.sh`、`run_probe.sh`、`run_suite.sh`、`verify_edges.sh`、`validate_production.sh`。具体的な引数・結果・SHA-256は[検証資料](../../../benchmarks/gng_followup_efficiency_20260924/README.md)を参照。

## Risk / Notes

個別段階の変動を全体の改善と混同しない。クラスタ管理単独の効果は小さく、0.1 mでは明確な短縮なし。候補XYZコピー削減は条件を保って再検討可能な見送り。

単一bag・固定乱数列の同値検証。任意環境での速度保証ではない。Emscriptenブラウザ、Jetson実機は未検証。準備時のGit所有者検査、終了監査の想定プロセス件数は実記録確認後に修正済み。
