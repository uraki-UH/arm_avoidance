# 2026-09-30 - 曲面パッチ特徴の保持と優先再評価

平面パッチの既存統計と曲率履歴を利用する再評価経路を実装済み。

## 要約

- 平面側の特徴: 重心・位置共分散・法線・局所間隔・平面残差の受渡し。全所属一致時のみ元平面の統計を利用、部分断片は別扱い。
- 履歴: 平面IDとノードID・生成世代の正確な所属照合。座標配列の二重保持なし。
- 再利用条件: 現在点の旧二次式への残差、中心・共分散・支持範囲、再評価期限の確認。距離許容値は既存の `max_patch_rms` / `max_point_residual` を利用。
- 処理順: 長期待機の繰上げ、前回有効特徴の再評価、保持曲面周辺、法線変化候補、その他。候補順の変更であり、形状採用条件の緩和なし。
- 境界・新規モデル探索: 上記評価順の利用。平面内部からの虫食い取り込み禁止と既存モデル残差検査の維持。
- 予算待ち: 古い有効曲率の出力禁止。未評価パッチを含む新規統合の延期。現入力への適合確認済み保持曲面は維持対象。
- 部分取得・支持分割: 同一曲率予算への計上、元全体特徴の部分領域への誤流用防止。
- 無効化条件: 世代・所属・座標系・時系列の不整合、形状逸脱、期限切れ。消失履歴の毎更新解放。

設定: [surface_model.yaml](../../../ais_gng_cpu/src/ais_gng/config/surface_model.yaml)、曲面処理の再起動後に適用。

```yaml
surface_model.enable_patch_history: true
surface_model.max_patch_fits: 32
surface_model.max_patch_refresh_frames: 5
```

- 適用範囲: `model` 方式かつ `surface_model.retention.enable: true`。曲面検出自体のON/OFFは既存設定のまま。
- 予算単位: 曲面更新1回あたりのパッチ曲率推定回数。境界追加推定は既存 `max_boundary_fits` の別予算、CPU時間の上限保証ではない。
- 互換経路: `enable_patch_history: false`、保持OFF、履歴なしの直接 `extract()` は従来の全再推定。
- 診断: 既存曲面JSONへ `num_curvature_fits` / `num_curvature_reused` / `num_curvature_deferred` とパッチ曲率の `is_deferred` を追加。追加topic・ROSメッセージ変更なし。
- C++互換性: 公開構造体・関数シグネチャ変更に伴う利用側再ビルドが必要。通常ais_gngビルド・installのシンボリックリンク参照を確認済み。

## 条件・検証

- 単体試験: 曲面97/97件、平面74/74件成功。微動・世代再利用・座標系変更・部分所属・待機公平性・支持分割予算・角と接壁の誤統合防止を含む。
- 最終比較: 4入力 × 旧版/履歴OFF/ON × 3反復、36/36試行成功。初期予測72秒、実時間59.25秒。
- 互換性: OFFの曲面JSONは旧版と全入力一致。ONの非空曲面の所属集合・各曲面所属IoUは全比較フレーム1.0、係数・残差には小差あり。
- 合成円柱: 曲面所属288/288点、遠方平面混入0点。微動時の最大点モデル残差1.293 mm、追跡ID変化0回。
- 曲率推定回数: 静止・微動円柱とも更新あたり8回 → 平均1.6回、再利用平均6.4回。比較4入力で予算延期0回、予算枯渇は単体試験で検証。
- 保存小規模入力の追跡ID変化: 旧版・ONとも5回。時系列追跡品質の改善根拠なし。

計測対象: `tracker.update()` のCPU時間、各試行の平均・p95の3反復中央値。GNG学習・平面生成・入出力変換・ROS配送・描画は対象外。

- 評価: 曲率推定部分の削減、全体時間の短縮は小幅。微動円柱のp95短縮は未確認。交差点は曲面0件の互換確認のみ、曲面精度・残差の評価対象なし。
- 制限: 全点・エッジ走査とモデル探索は残存。平面枚数による候補・表示条件は変更なし。実bagライブの表示・新規曲面検出精度の向上は未検証。
- 実行状態: 自身のビルド・試験プロセスは全終了、既存bag・TF・Viewer・コンテナ状態を維持。ROS setupの `set -u` 不整合による試験前エラー1回は修正後に再実行。
