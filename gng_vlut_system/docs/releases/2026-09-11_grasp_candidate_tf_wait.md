# 2026-09-11 - 把持候補のTF遅着による色戻りの抑制

## Summary

観測時刻のTFを短時間待機し、連続入力時に到達評価が未評価へ戻る現象への対処。

## Changed

共通候補publisherの時刻指定TF取得に有限の待機時間を追加。

## Added

動的TFの15 ms遅着、観測時刻での補間、初回配信の到達状態、時間切れ時の未評価を検証する回帰テスト。

## Fixed

実配信で候補時刻より最新TFが約15 ms遅れ、20 Hzの新規候補がほぼ毎回UNKNOWNとなる状態を確認。
5 Hzの再評価時だけINSIDE色が出た直後に、新規候補のUNKNOWN色で上書きされる配信列を確認。
候補IDとノード色の対応自体に不整合はなし。

## Removed

なし。

## Behavior Impact

異なる座標系でTFが遅着した場合のみ、取得までの短時間待機。TF取得済み・同一座標系・空候補では待機不要。
時間切れはUNKNOWN。過去の状態の流用や最新TFへの代替はなし。時刻ゼロの入力の最新TF使用は従来どおり。
把持面の採用条件、候補追跡、配色、Viewerの処理に変更なし。

## Topics / Params / Messages

- `reachability_tf_timeout_sec`: 共通候補生成ノードのTF待機上限 [秒]。既定0.05、0で待機なし。
- トピック・メッセージ定義の変更なし。

## Verification

Dockerの`gng_cpu_container`内でビルドとCTest、既存の候補ノード色の統合テストを実施予定。

## Risk / Notes

TF停止時にも待機上限内の遅延が発生。登録セルによる位置到達性であり、姿勢IK・衝突・把持成功の保証ではない。
ビルド前から動作中の候補生成ノードには再起動が必要。既存プロセスの停止・再起動は未実施。
