# 2026-09-25 - CPU GNGの重点サンプリングを共通化

## 1. 要約

既存入力ボクセルを共有する評価器と抽選処理へ、把持・境界重点を移行。
通常・unknown・重点の配分を共通化し、総学習回数を維持。

- 各条件はセル単位の重みを返す規則として登録。細かい位置判定が必要なセルだけ元点を評価。
- 元点数・最近傍ノードと生成世代・任意の外部属性表を参照可能。同一セル内ノード数は要求時だけ共通集計。
- ラベル追加のたびに抽選器へ分岐や全点走査を追加する構成を回避。
- セル内で重みが一定なら、元点候補の展開を省略。確認用点群は必要時だけ生成。
- 非平面・小規模平面・点群とノードの密度差による評価式は未追加。削除済み非平面重点の復活なし。
- 2026-09-26追記: 公開サンプリング定義を既存`api.h`、把持・境界の規則生成を各機能ヘッダーへ統合。専用ヘッダー2件を削減し、抽選本体・観測APIの分離は維持。

## 2. 条件・検証

| 項目 | 内容 |
| --- | --- |
| 対象 | CPU GNG、把持・境界重点のROS接続 |
| API | `api.h`の規則登録、統計取得、条件別候補取得。旧`sampling_api.h`のincludeは変更が必要 |
| 設定 | 既存把持・境界YAMLを継続。新条件はC++評価器と必要な設定読込の追加が必要 |
| 出力 | `/downsampling/grasp`は共通候補を再利用。GNG入力範囲フィルタ適用後の点のみへ変更 |
| 互換性 | 候補条件・配分を維持。抽選順・乱数消費順の変更により、同一seedのグラフ一致は保証なし |
| 対象外 | 入力上限の間引き、unknown候補XYZ保持、動静分類、ノード配分保証 |
| 導入 | `gng_cpu`・`ais_gng`をビルド済み。稼働中GNGは利用者による再起動が必要 |

候補属性を読む際は、ノードID再利用を生成世代で検出。前フレームの情報には利用側の失効判定が必要。
評価中の不正値・例外は共通規則の候補を破棄し、通常学習と有効な旧API候補へ退避。
セルだけの条件は追加の元点評価なし。ただし条件数・重なりに応じて候補数と準備時間は増加。
ノード数集計・属性表作成・利用側の探索を無償と扱わず、各機能追加時に別途評価。

Releaseビルド2パッケージ、CPU CTest 23対象、ROS単体4対象が成功。
実bagの変更前後比較480フレームと、最終ビルドでの候補失効16フレームを検証。
非空Tmap、把持候補の独立BBox判定との座標・順序一致、失効後の空出力、廃止Publisher不在を確認。
全体処理時間は今回の条件でほぼ同等。単純なセル条件1／4／16個の準備は0.339／0.781／2.700 ms。
数値の対象・条件・除外範囲は[検証資料](../../../benchmarks/common_sampling_20260925/README.md)に集約。

実物体の追従性・認識精度、新しい評価式、非自明TF、Viewer実描画は今回未検証。
既存ビルド警告は残存。規則は1入力分だけ有効で、APIはCPU専用。
試験用ノード・ベンチマーク・ビルドの全セッション終了。既存GNG・bag・Viewer・コンテナは停止せず維持。
起動コマンドと停止確認は検証資料に記録。
