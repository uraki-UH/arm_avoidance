# 2026-09-24 - CPU GNGの法線・曲率・ラベル処理の効率化

## Summary

隣接ノードの座標・法線を連続配列から参照し、差分ベクトルを再利用する実装を本番CPUへ反映。実bagの比較で法線・曲率・ラベル部分を約12〜16%短縮。同じ入力・乱数・時間刻みの1,410組で全比較項目が一致。

## Changed

- `Labelling`に座標と法線の連続配列を追加し、毎フレームの有効ノード値を集約。大きなノード構造体への隣接参照を削減。
- `normal_vector`の中心位置・隣接差分を再利用。外積の組、正規化、符号判定、加算順を維持。
- `rho`で、確定した全ノード法線の連続配列を参照。法線確定後に曲率・ラベルを計算する順序を維持。
- バッファは初期化時の確保と再利用。2万ノードで約480 KB。

## Added

位置変更、接続順変更、欠番、ID再利用、サイズの異なる再初期化、同一形状でのLPF継続を対象とする回帰テスト。

## Fixed

法線ループ中の差分ベクトルの重複計算と、隣接ノードの大きな構造体への反復参照。

## Removed

なし。

## Behavior Impact

全有効ノードの法線・曲率・ラベルを毎フレーム更新。学習4,000回、全点照合、入力フィルタ、重点配分、ノード・エッジの寿命、クラスタ、観測・統計・差分機能は維持。近似法線、更新間引き、fast-mathの追加なし。

比較コピーだけ乱数・時間刻みを固定。本番は従来の乱数・実時間を使用。
起動中の既存GNGは原子的置換前のライブラリを保持。停止・再起動は実施せず、新実装は次回の通常起動から有効。

## Topics / Params / Messages

変更なし。公開C APIのエクスポート集合も一致。内部C++メソッドは連続配列への省略可能な引数を追加し、単独呼出し時のノード直接参照を維持。

## Verification

既存GNG・Viewer・bag再生を継続した状態で、Release＋既存LTO、CPU 0固定。同じ交差点bag、入力約16万点、ノード上限2万、`node.grid=0.5`。連続300フレームの先頭50フレーム除外平均:

| voxel幅 | 法線 | 曲率・ラベル | 法線周り合計 |
| --- | ---: | ---: | ---: |
| 0.1 m | 3.564→3.120 ms | 2.024→1.576 ms | 5.588→4.697 ms（16.0%短縮） |
| 0.5 m | 2.226→2.042 ms | 1.762→1.454 ms | 3.988→3.497 ms（12.3%短縮） |

実行順を入れ替えた3試行共通区間の中央値でも、法線周りは5.523→4.637 ms／3.986→3.450 msへ短縮。

- 計2,660フレームを実行。保存した基準の再利用を含む1,410組で、法線、曲率、座標、グラフ、クラスタ、入力ラベル、voxel対応、候補数が一致。全フレーム4,000回学習。
- 拡張機能90組で観測、共分散・支持統計、重み付き重点入力、学習イベント、グラフ差分も一致。
- 比較版51件・追加回帰1件・本番18件の計70件が成功。回帰テストの初回登録漏れとROS環境未読込による失敗は修正後、実行1件の成功を確認。失敗ログも保存。
- インストール済みの実時間・非固定乱数版で実点群30フレームと拡張機能の動作確認が成功。
- 実際の引数なし`cb`で30パッケージが57.3秒で成功。`gng_wasm_core`のstderr出力あり、失敗・中断なし。通常版`gng_cpu`は1件。
- 本番ライブラリを原子的に反映。公開API不変、Releaseの`-O3`・LTOを確認。

## Risk / Notes

法線周りの短縮率をGNG全体の短縮率として扱わない。全体は300フレームで109.083→106.476 ms／37.592→37.815 ms。3試行共通区間の中央値は109.719→109.110 ms／37.573→37.512 msで、特に0.5 mの改善は小さく試行ごとに増減。

0.1 mでは変更後も全点照合・重点候補生成が約80.2 msを占める。全体の時間差には他段階の変動も含む。単一bag・同一乱数列／時間刻みでの一致検証であり、任意環境での速度・完全一致の保証ではない。
