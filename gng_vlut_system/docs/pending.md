# 保留中の作業

取り組む意向はあるものの、時間・優先順位・依存作業・環境などの都合で停止している作業の台帳。
採用・方式そのものを検討中の案は [TASK_CANDIDATES.md](TASK_CANDIDATES.md)、不採用判断は [reject.md](reject.md) に分離。

## 記載項目

- 保留日・対象: 作業名と対象範囲。
- 保留理由・判断根拠: 時間不足、他作業優先、データ・環境待ちなど。ユーザー指示と提案の区別。
- 完了済み範囲: 実装・検証済みの範囲と [progress.md](progress.md) 等へのリンク。未着手ならその旨を明記。
- 再開条件: 何が揃えば再開できるか。日付が未定なら未定と明記し、架空の期限を設定しない。
- 次の一手: 再開直後に行う具体的な作業と必要な資料・コマンドへのリンク。

## 移動ルール

1. 保留が明示された作業だけを登録。長く更新されていないことだけを理由に保留扱いにしない。
2. 移動時は完了済み範囲と未完了部分を保持し、元の台帳には必要な場合だけ参照リンクを残す。同じ作業本文の二重管理なし。
3. 再開が決まったら [TASK_LIST.md](TASK_LIST.md) へ未完了部分を移し、ここの項目を除去。保留・再開の実施事実は `progress.md` へ短く記録。
4. 方式の再検討が必要になったら `TASK_CANDIDATES.md`、不採用が決まったら `reject.md` へ移管。移管は判断根拠を確認した範囲だけ。
